## 1. 目标、证据与边界

本计划只修复现有清洗链路中的过严校验、咨询方案/方法遗漏、混合 PDF 路由、失效去重，并验证四个既有模型策略的 Batch/Realtime 合同与知识库效果一致性；不重建清洗系统、跨来源 Registry 或 Dify DSL。部署隔离、远端预检、费用与清理边界见独立文件《执行计划的测试部署补充》；两份计划相互引用，不合并。

最初问题的历史定位如下（不能当作当前修复已完成的证明；当前未闭环项见第 6 节）：

- `personal_business_consultation` 的当前契约把分类、阶段、背景条数、3--6 条中文检索问法和特定 evidence 类型当作整份结果的硬门槛；又将方案限制为必须逐字等于 advice 引文，因此会静默删掉忠实整理的方案。
- 现有主清洗路径只接收 `cases`，没有稳定产出同次生成的候选方法；这不能以“跨来源晋升条件未达到”解释。目标是自动产出有来源边界的候选方法，重点覆盖产品方案、产品定价、权益等完整解决方案场景。单来源经验不得包装成已验证的普遍规律。
- 帖子策略的来源引用最多 50 项是固定上限；部分字段及 `keep_block_ids`/`drop_block_ids` 的全覆盖要求也会将本应可用的知识单元连带拦截。
- OCR 服务和离线模型仍存在。混合 PDF 被 `_classify_pdf_type()` 标记为 `review` 后，转换层直接返回空页且未调用 OCR，最后被误报为“清洗后正文为空”；这不是 OCR 服务不存在。
- 失效或已删除的远端成果仍可能参与去重，造成书籍重新入库被拦截；有效的当前成果才可复用。

## 2. 已确认处理规则

| 情况 | 新链路的确定行为 |
| --- | --- |
| 模型调用异常，或逐单元处理后没有任何可用核心内容 | 对同一匿名化来源快照最多完整重跑一次；两次仍无核心内容则 `failed` |
| 有若干独立可用单元，其他单元或辅助字段不合格 | 保留通过来源、隐私和事实校验的单元；记录未采用/降级原因，不追加模型调用 |
| 模型明确判断不适合商业知识库，且该判断及来源证据通过校验 | `excluded` |
| 未经校验的排除、OCR/转换/模型/Dify 技术失败、空响应或结构错误 | `failed`，不得记为 `excluded` |
| 已有同源且当前仍有效的成果 | 成功复用并记录 `duplicate_noop` 关联；不是内容排除 |
| 重复目标已证明删除或失效 | 解除该精确关联，按既有流程允许重新发布；发布技术失败才为 `failed` |
| 重复目标暂时无法确认可用（读取超时、格式异常或网络错误） | 保留可重试的验证/发布状态；既不视为有效重复，也不视为已删除而盲目新建 |

具体约束：

- 新链路不产生新的 `review_required`，不以原文 Markdown 或占位正文自动兜底发布；保持历史状态和接口兼容，不自动改写历史数据。
- 最多两次完整模型生成必须跨 HTTP 客户端、realtime Worker、Batch Worker 和消息重投统一计数，不能叠加成第三次。正常运行继续默认 Batch 关闭；仅允许在部署补充规定的隔离验收门禁全部成立时显式启用 Batch acceptance。
- 每个知识单元独立判断。认知分享必须有依据且可独立理解；咨询案例必须有问题和理解它所必需的背景、目标、约束。不可删除关键条件后保留会误导的结论。
- `problem_category`、`case_stage`、`topic`、`time_sensitive`、`confidence`、细粒度 evidence 分类、检索问法数量或中文形式是辅助字段：缺失或不规范允许沿用安全空值/默认值或隐藏呈现，不编造，不单独阻断入库。
- 仍为硬门槛的是来源真实可回溯、引用 ID 合法、匿名化、事实不虚构、不同背景策略不混用，以及正常检索所需的内容与来源关联。
- 使用批次既有处理详情记录采用、降级和未采用原因，不增加状态体系或业务表。

## 3. 最小实现改动

### 3.1 模型请求、契约和单元级容错

- 将大模型 JSON 的工程化防线落实在既有请求/解析层：明确核心字段与辅助字段、Schema/类型宽容归一化、有限且可计数重试、字段级可观测错误。参考《大模型 JSON 输出稳定指南》，只复用适合本项目的容错和重试原则，不引入另一套清洗框架。
- 所有受影响的大模型清洗策略采用相同的“核心内容为零才完整重跑”规则；`recent_activity` 不改，尤其不改变它经共享请求构造函数获得的模型参数、解析或重试行为。
- 帖子取消 50 个合法来源块的机械上限与 `keep/drop` 必须覆盖全部来源块的要求；未知引用、遗漏来源导致无法追溯、虚构数字/日期、隐私泄露和没有可检索核心知识仍应拒绝对应单元。
- 咨询按 case 逐项归一化、校验、保留。分类、阶段、检索问法、背景/问题 evidence 标签不应单独否定整份会议；一个不安全或无来源 case 不得拖住其他可用 case。
- prompt 只描述当前契约；删除旧 `consulting_case_v2`、人工审核、原文兜底及相互矛盾的固定字段数量要求。兼容历史输入放在解析层，不让 prompt 混杂多种结构。

### 3.2 咨询问题、解决方案与方法

- 继续使用 `record_type=consulting_case` 和 `record_type=methodology`，不新增 metadata 枚举。
- 每个 case 尽量完整呈现“问题—必要背景/目标/约束—原文解决方案—适用条件或限制”。方案可以忠实整理/改写，但必须以来源 evidence 回指；取消“方案字段必须逐字等于 quote，否则删除”的过滤。
- 默认记录“本次未提取到方案/方法”；只有实际对照原文证实后，才能表达“原文未提供”。模型漏提或过滤误删是质量缺口，已有可用 case 时不得因此再调用模型补提。
- 在同一次咨询生成中产生方法候选及其 case/evidence 关联，或由同次已产出 case 的证据形成等价候选。方法按“要解决的问题、适用场景、判断依据、执行步骤、限制与缺失信息”据实组织。当前使用 `case_scoped`：一个语义连贯 case 内的多个相关问题可共同形成候选，不跨不同 case 拼接，也不机械地把每个问句拆成孤立 case。
- 相同问题在产品形态、目标、资源、阶段等背景不同的情况下，策略可不同，必须分别保留；去重/合并不能只用问题文字相似度。没有证据时不编造方法、价格、权益、结果或成功承诺。

### 3.3 混合 PDF、OCR 与去重

- 对普通混合 PDF，保留可靠文字层页面，只对 image-only 或低可靠页面调用现有 RapidOCR，按原页码顺序合并；不更换 OCR 服务、不静默丢页。
- 维持咨询含图片 PDF 的隐私覆盖：图片页必须进入 OCR/匿名化检查，不能因选择性 OCR 绕过受保护身份扫描。
- 保留现有 OCR 资源、置信度、页数限制和低质量重试；缺页、关键事实冲突、OCR 失败或超限必须给出准确 `failed` 原因，不再统一压成 `CONTENT_EMPTY_AFTER_CLEANING`。
- 去重的“可复用”条件必须同时验证远端成果仍有效；`remote_deleted_at`、失效 Dify ID 或不能确认可用的历史关联不得拦截上传或发布。删除权限继续只由精确关联授予。

### 3.4 隔离测试支持（与部署补充配套）

- 复用现有容器、镜像、Worker、清洗和发布流程，增加最小隔离 Compose/环境/启动与回滚资产，不另建业务系统。
- 测试模式在服务端强制 general-only；不能只靠 UI 隐藏课程入口。测试 Dataset 固定为 `19206ce0-80a4-4a93-aa86-63e3385d2b2a`，详情见部署补充。

### 3.5 Batch/Realtime 一致性与 canonical 发布

- 需要模型 Batch/Realtime 一致性验证的策略准确限定为 `personal_business_consultation`、`wechat_public_account_cognition`、`zsxq_post`、`xiaobot_post`。`recent_activity` 保持 realtime-only；`course_route_catalog` 不属于本次对照范围，但不得破坏其既有功能。
- 四个目标策略全部做免费、本地、确定性的请求与结果合同一致性验证；真实付费对照只覆盖 `personal_business_consultation` 和 `zsxq_post`，分别代表咨询 case/methodology 与帖子 shard 两类产物。
- 一致性按模型/Prompt/messages/参数、单元采用或拒绝、来源/隐私/事实、咨询方案与 `case_scoped` 方法、帖子引用、record type、受控 metadata、chunking、parent/child、幂等、Dify 索引/回读和检索业务效果判断；不要求模型措辞、provider ID、远端 document ID、时间戳或完成顺序逐字一致。
- Realtime 是不同 digest 时的固定 canonical 候选。两 transport 均须完成真实模型生成及独立的来源、隐私、语义/合同、metadata、chunking、parent/child 与发布计划验证；共用发布路径以本地/fake 合同证明。任一 transport 未独立合格时 parity 失败，两份都不发布，不以另一边成功掩盖失败且不自动追加第三次调用。两边通过且 digest 相同时发布 Realtime，Batch 以共享有效成果的远端复验形成 `duplicate_noop`；digest 不同但业务语义等价时只发布 Realtime，并由其完成真实 Dify 索引、回读和检索，Batch 仅保留未发布的脱敏对照而不得宣称独立远端检索；语义不等价时两份都不发布。不得双写或新建 Dataset；若将来验收要求两个不同 digest 均独立远端索引，须先作为不相容项集中确认。
- 不根据主观“哪份更好”临时改变 canonical transport，不为对照默认向固定 Dataset 写入两份语义重复文档，也不创建新 Dataset 或扩大清理授权。

### 4.2 验收项

- 指定咨询样本逐项做匿名化的“原文问题—方案—方法”对照：已存在的方案不得被逐字过滤误删；相关问题能形成有边界的候选方法；不同背景下的不同策略分别保留；原文确无方案时不编造。
- 验证有一部分不合格单元或辅助字段缺失时，其他独立可用单元仍可发布；没有任何核心内容才完整重跑一次。验证不存在第三次生成、新 `review_required` 和源文兜底。
- 验证超过 50 个合法引用可通过，未知引用、无来源核心内容、虚构业务事实、匿名化残留和未经验证的排除仍被拒绝。
- 按实际文件 SHA-256 验证图像页进入 OCR、页序和文字页均保留；分别记录总页数和实际 OCR 页数。历史“239 页中需 OCR 9 页”与“独立 9 页书籍”不能未经核对视为同一文件。覆盖纯文字、纯扫描、空白、低置信度、超限及识别失败的准确错误分类。
- 验证有效重复复用，远端已删除/失效关联不阻止重传，发布重试/补偿不留下重复或半成品。
- 四策略完成本地确定性 Batch/Realtime parity；两项真实付费对照分别证明两种 transport 的生成与本地合同独立合格、canonical 裁决、同 digest 的共享有效成果/`duplicate_noop` 或不同 digest 的 Realtime 单份远端发布及 Batch 脱敏证据保留。不同 digest 的未发布 Batch 不要求、也不得冒充独立远端索引或检索。
- 先按策略分组运行本地回归，所有失败先记入脱敏问题清单，结束本轮后统一分析和修复，再从该组测试起完整回归；不能靠放宽校验、允许空正文或让单一样本通过宣称完成。
- 通过聚焦测试、仓库 Quality 和独立审查后，再按《执行计划的测试部署补充》做 jx 只读预检。预检证明预算、隔离、镜像、数据归属和正式健康均成立后，按已确认范围执行六类真实样本、两项真实付费 Batch/Realtime 对照和 Dify 全链路；缺少项目要求的精确命令批准时只暂停对应命令并集中处理。
