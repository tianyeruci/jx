补充固定判定：

- 一个查询可覆盖多个关键点；查询集不能在看到结果后改成更容易通过的内容。
- 普通知识允许综合多个合格来源；针对某来源的具体事实不得由其他来源冒充。模型可提供一般建议，但不得声称不存在的事实有来源支持。
- “部分单元成功”是合法运行状态，但如果丢失预标关键内容，该样本仍不能通过内容验收。
- 负向故障优先在本地或受控临时对象上注入；不破坏最终保留文档或原有文档来制造故障。
- 原有自动测试逐项判定沿用、调整或退役，保留理由。现有必要回归继续执行，不新增远端容量压测。
- 旧验收 runner 的自动审批和等待逻辑先审查后复用。OCR 按当前任务超时判断；Batch 按实际完成窗口跟踪，提交成功不能算完成，等待超时不能触发重复提交。

## 5. 集中修复、复测、恢复与最终交付

**执行顺序固定为：**统一合同与冻结预期 → 免费检查和阻塞修复 → 完成预算准入及 ys 配置生效 → 真实验收 → 集中定位根因 → 最小修复 → 受影响复测 → 清理与交付。

普通失败保留完整证据后继续其他独立测试；涉及隐私、数据完整性、费用或共享资源时，停止依赖该风险的动作。源码保持一个写入者，其他 Agent 做只读分析与验证。不能用发现一个失败就修改一处、重新跑全部的方式替代根因归并。

**复测按变化阶段决定，费用和调用历史始终保留：**

| 变化 | 必须更新的证据 |
|---|---|
| 仅凭据/运行配置 | 配置生效、鉴权、相关服务和最小实际调用 |
| 转换、OCR、清洗输入、Prompt 或模型配置 | 受影响样本的转换、模型及后续内容证据 |
| 仅解析/校验/发布逻辑 | 用已有真实 Provider 结果重新验证当前处理；重跑受影响发布、回读和检索，不自动重复付费生成 |
| Dify DSL/发布版本 | 对应 App 的参数、输入、相关业务/SSE/RAG |
| Dify 文档状态或索引变化 | 对应文档的分块、Metadata、正文和检索 |
| 纯报告修订 | 文档检查；不使运行结果自动失效 |

每条沿用证据必须与当前对应阶段的输入、配置及产物指纹匹配。不能将不同版本的成功结果简单拼成最终通过；免费复验也不能冒充一次新的真实模型调用。

**迁移与恢复边界：**

- ys 已在当前 head，本轮不重复迁移。
- 在 ys 专用数据库内的隔离临时 schema，用合成历史数据验证 prior revision→head、旧行默认值、业务状态保留、重复 upgrade 和旧记录读取；不用正式业务数据。

**保留与清理边界：**

运行中及时将样本与 batch/file/item/shard/远端文档的精确关联、产物摘要、费用及回读证据保存到受保护报告中，避免被正常保留期清理。原始样本仍保留在用户给定目录；服务器上传副本沿用既有清理行为，不新增永久存储机制。

**完成条件：**全部 15 份样本及 EV-01～EV-08 达到固定标准；最终候选、Dify 发布版本和证据可对应；预算及必要治理门禁有效；最终成果保留、临时产物清理；七个默认服务恢复且 Batch 关闭。
