# PDF OCR 清洗与语义质量保障改造计划

## 总结

所有影响方案的需求已确认：

- 覆盖全部 OCR PDF 清洗策略。
- 非关键不确定内容可整段删除；关键内容不确定则整份复核。
- 非关键说明允许结合上下文重写；关键事实只允许最小纠错。
- 可疑页面执行高分辨率二次 OCR，再经过“重写＋独立验证”两个模型阶段。
- 只检查当前 PDF 内部语义和逻辑，不与知识库或外部资料比较。
- 自动入库以准确率优先：可以损失非关键信息召回率，但不得保留已知错误、语义不通或逻辑矛盾内容。

`pdfplumber` 不提供 OCR，因此继续负责文字型 PDF，扫描型 PDF 使用现有 PaddleOCR 适配器。[pdfplumber 官方说明](https://github.com/jsvine/pdfplumber/blob/stable/README.md)

## 实现方案

### 1. PDF 分流与 OCR

在现有转换模块上改造，不创建独立 `mdconvert` 工程：

- 一页 PDF 探测第一页；多页 PDF 严格探测前两页。
- 页面有效文字不少于 40 字且乱码比例不超过 10%时判定为文字页。
- 有效文字少于 20 字且主要栅格图片覆盖超过页面 50%时判定为图片页。
- 前两页均为文字：整份使用 `pdfplumber`，忽略其中嵌入的图片。
- 前两页均为图片：整份使用 PaddleOCR。
- 两页类型不一致或无法确定：`PDF_TYPE_REVIEW_REQUIRED`。
- 分流后不切换引擎；但出现空页、缺页或页数不一致时进入复核。
- OCR 最多处理 10 页；超限返回 `OCR_PAGE_LIMIT_REVIEW`，不生成部分文档。

OCR 第一遍按 200 DPI 渲染；满足以下任一条件时，仅对问题页按 300 DPI 重新识别：

- 文本行置信度低于 `0.90`。
- 出现乱码、异常断词、重复行或明显残句。
- 表格行列归属不稳定。
- 两次识别在数字、时间、主体、否定词等关键内容上不一致。

二次 OCR 后仍存在关键冲突时直接复核；非关键冲突交给语义阶段处理。页面临时图片只存在于任务临时目录，并在 `finally` 中清除，不写入日志或业务存储。

### 2. OCR 质量门禁

- 文本行置信度 `>=0.90`：可进入自动处理。
- `0.75–0.90`：属于可纠错候选。
- `<0.75`、低可信行占比超过 10%、空页或缺页：复核。
- 以下内容属于关键事实：
  - 数字、金额、比例、日期和时间。
  - 人名、组织、产品及编号。
  - 否定词、程度词、条件和范围限定。
  - 结论、定义、决策、行动项、责任人、风险和期限。
  - 表格及其字段归属。
- 关键事实置信度低于 `0.90`、两次 OCR 不一致或缺少可信来源时，不允许模型猜测或删除，整份进入复核。
- 表格结构可靠时生成 Markdown 表格；归属唯一但结构不完整时线性化并附加 WARNING；存在串列、跨列歧义或关键数字归属不明时复核。

### 3. 全部 OCR PDF 的语义处理

OCR 通过隐私检测后，所有策略统一执行两个文本模型阶段；页面图片不发送给模型。

第一阶段为受约束重写：

- 输入包括稳定块 ID、两次 OCR 候选、置信度和受保护事实清单。
- 非关键说明允许调整语序、合并残句和结合当前 PDF 上下文重写。
- 关键内容仅允许错别字、断词、标点等最小修正，受保护事实必须逐项保持。
- 模型必须为每块返回 `keep/rewrite/drop/review`、修改后文本和理由。
- 无法恢复的非关键块按完整段落删除，不在入库 Markdown 中留下占位符。
- 来源本身存在非关键矛盾时删除相关冲突块，不允许模型自行选择一个版本；涉及关键内容则复核。

第二阶段为独立验证：

- 同时读取原始 OCR 候选、重写结果、块映射和受保护事实。
- 检查是否新增、删除或改变事实，是否产生指代错误、因果倒置、前后矛盾、残句或语义跳跃。
- 验证失败的非关键块删除；关键块或文档级逻辑失败进入复核。
- 只有验证结果为 `pass` 且不存在未处理问题时，才生成最终 Markdown。

单份文档发送给模型的 OCR 正文最多 24,000 Token；超过限制返回 `OCR_SEMANTIC_INPUT_LIMIT_REVIEW`，禁止截断后入库。咨询会议总结在语义验证通过后，再执行现有信息提取模型，因此最多产生三阶段模型调用；其他 OCR 策略为两个阶段。

## 内部接口与运行方式

新增内部结构：

- `PDFRouteDecision`
- `OCRBlock`：块 ID、页码、类型、文字、置信度和候选版本。
- `ProtectedFact`：来源块、事实类型和不可改变值。
- `SemanticRewriteResult`
- `SemanticVerificationResult`
- 扩展 `PDFConversionResult`：路由、Markdown、WARNING、审计信息、复核状态和错误码。

建议配置默认值：

```text
PDF_OCR_ENABLED=true
PDF_OCR_MAX_PAGES=10
PDF_OCR_RENDER_DPI=200
PDF_OCR_RETRY_DPI=300
PDF_OCR_AUTO_CONFIDENCE=0.90
PDF_OCR_MIN_CONFIDENCE=0.75
PDF_OCR_MAX_LOW_CONF_RATIO=0.10
PDF_OCR_SEMANTIC_MAX_INPUT_TOKENS=24000
PDF_OCR_CPU_THREADS=4
```

运行与失败处理：

- 所有 PDF 任务进入独立 `ai_ocr` 队列；非 PDF 保持原队列。
- OCR Worker 使用单并发、`prefetch=1`、每任务回收子进程、软/硬超时 540/600 秒。
- OCR 镜像安装与其他服务相同 SHA 的应用 wheel，离线预置 PaddleOCR、PaddlePaddle、页面渲染依赖和模型文件。
- 模型目录及文件在启动时校验 SHA，禁止运行时联网下载。[PaddleOCR 安装说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/installation.en.md)
- OCR 或模型技术异常先自动重试；重试耗尽后为可定位的 `failed`，不得输出未验证 Markdown。
- 文档内容不确定才使用 `review_required`。
- HTTP 接口、响应字段和既有状态语义不变，不修改已完成对接的接口文档。

## 测试与验收

- 分流测试：一页/两页文字、扫描、类型冲突、模糊页、文字 PDF 内嵌图片、后续空页、超过十页。
- OCR 测试：两次识别一致、普通错字差异、数字/日期/否定词冲突、低可信比例和页数完整性。
- 语义测试：
  - 非关键残句可重写并通过验证。
  - 错误因果、主体错位和前后矛盾不得进入最终 Markdown。
  - 数字、时间、否定词及实体变化必须被验证器拒绝。
  - 验证失败的非关键块删除，关键块触发复核。
  - 不得生成原始 OCR 中不存在的新事实。
- 表格测试：可靠 Markdown、确定归属的线性化、跨列歧义复核。
- 隐私测试：隐私检测在模型调用前执行；正文、原始文件名和修改内容不出现在普通日志或公开 Metadata。
- 队列和离线镜像测试：创建、重试、维护任务路由一致；无网络环境可启动并完成真实 OCR。

真实样本验收标准：

- 两个文字咨询 PDF 继续使用 `pdfplumber`，输出无非预期变化。
- 三页扫描咨询 PDF 页覆盖率 100%。
- 自动入库样本的关键事实准确率必须为 100%，不得存在已知语义矛盾或模型新增事实。
- 非关键内容召回率只记录，不作为发布阻断条件。
- 三页 OCR 不超过 120 秒，十页不超过 600 秒，OCR 容器峰值 RSS 不超过 7 GB。
- 任一准确性门槛不满足时，OCR 自动入库保持关闭，只允许复核路径。
