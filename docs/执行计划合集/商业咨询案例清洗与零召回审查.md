# 商业咨询案例清洗与零召回审查

## Summary

- 输出一份证据审查报告，明确回答：问题是否问错、零召回发生在哪一层、当前清洗成品是否适合案例型 RAG。
- 结论分为“当前样本的确定事实”和“整体策略的条件性建议”，不以单个样本证明全局有效性。
- 同时审查清洗结构和 Chatflow 检索链路；只提供优化方案，不修改代码、Dify 或知识库。

## 审查与建议内容

- 对照原始 DOCX、当前清洗 Markdown、线上索引/分块、两次真实零召回记录及最小检索 A/B，形成完整因果链。
- 从信息完整性、事实状态、隐私、适用背景、证据等级、语义分块和检索表现评估当前成品。
- 对优化包逐项给出“采用、调整后采用、不采用”，重点审查决策单元、显式子块、严格 JSON、来源覆盖、E1–E3、长度限制、Metadata、原文件保留和影子迁移。
- 给出按优先级排列的方案：
  - P0：修正零召回涉及的 Rerank/阈值配置并建立参数 A/B。
  - P1：将章节式摘要改成“共享背景＋决策单元”，使用显式子块边界。
  - P2：补充事实状态、隐私、未验证结果和时效门禁。
  - P3：用多样本黄金集校准长度、Schema复杂度和召回参数。
- 不改变现有 HTTP 接口；如建议扩展清洗 JSON 或 Dify Metadata，将明确标为后续候选，不视为本轮实施。

## Test Plan

- 目标问题及同义表达：指定相关案例进入 Top-5，回答至少提供一个适用案例。
- 反例问题：无受众、成熟大团队、禁止分销、交付产能不足时不得机械套用案例。
- E1 案例：允许作为“未验证的咨询方案案例”，不得表述为成功案例或已证明有效。
- 内容门禁：关键数字、否定、计划/结果状态不变；姓名、组织、联系人和受保护映射不进入正文或 Metadata。
- 分块门禁：每个决策单元独立成块，不从句中间切开；子块带主题、必要背景、建议、结果状态和边界。
- 正式策略有效性需再用 10–20 份差异化咨询样本验证，比较 Recall@5、context precision、回答忠实度和错误案例率。

## Assumptions

- 保留脱敏后的价格、人数、销量和日期等适用性信息，并标注时效。
- 无后续结果的材料按 E1 使用，不称为成功案例。
- 指定案例 Top-5 为验收标准，不强制稳定 Top-1。
- 结果直接在当前对话中输出，不创建文件、不执行任何线上写入。
