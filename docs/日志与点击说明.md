# AI 管理服务 V2 日志与课程点击说明

> 本文规定统计口径和后台行为。V2 为唯一基线；当前实现若与本文不符，应按测试驱动方式修正。

## 1. “点击次数”的含义

- **PV（点击次数）**：课程签名链接被成功验证并准备跳转到正式地址的次数。同一人连续点击 3 次，PV 增加 3。
- **UV（点击人数）**：同一匿名用户在同一天点击同一课程只计 1 人，仅作辅助指标。
- 无效签名、过期签名、课程不存在/停用/未审核、被安全策略拒绝的请求不计数。
- 点击只表示跳转意图，不表示学习、购买或完成课程，不推进学习路线。

## 2. 记录与落库

有效 `/r/{token}` 请求按顺序执行：验签 → 查询课程当前状态 → Redis 原子增加 PV、写匿名 UV、加入 dirty 日期 → 返回 302。若计数写入失败，不静默丢弃：记录错误并按产品错误策略返回可重试响应，避免“已跳转但完全无统计”。

夜间任务遍历全部 dirty 日期，将 Redis 的绝对计数幂等 upsert 到 `course_click_daily`；数据库成功后才清理 dirty 标记。任务中断后下次继续，不限于固定昨天。Redis Key 至少保留 30 天，PostgreSQL 日汇总长期保留。

## 3. 点击查询

`GET /internal/v1/admin/course-clicks` 使用 `X-Admin-Token`，支持：

- `course_id`、`date_from`、`date_to`、`page`、`page_size`；
- 每日 `clicks`、`unique_users`；
- 查询区间 `total_clicks`、`total_unique_users_daily_sum`；后者是每日 UV 之和，不代表跨日去重人数；
- 当日或未落库日期的 Redis 实时值、`persisted_through` 和数据来源标记；
- 按区间点击次数排行。

Streamlit “课程点击”页默认展示总点击次数、每日趋势和课程排行，UV 放在次要位置。

## 4. 日志分层

### stdout 结构化日志

用于技术排障，覆盖 API、Worker、Scheduler。每条为单行 JSON，包含时间、等级、组件、事件代码、request/task ID、资源哈希、耗时、状态和构建版本。容器日志或日志平台负责采集和轮转。

### `system_event_log`

用于后台查询必要操作与错误，不代替完整容器日志。至少记录：

- 会话删除、反馈、停止失败；
- 课程 dry-run/publish、Dify 对账和缓存重建；
- 清洗批次创建、自动/人工重试、索引失败和补偿；
- 摘要失败、历史清理跳过、点击落库、夜间维护；
- 外部删除任务和所有未处理异常；
- 管理鉴权失败的聚合安全事件（不得写 Token）。

已转换为稳定 HTTP 错误的服务异常，如知识库读取失败，可在明确捕获点附加受控诊断字段：`phase`、`exception_type`、脱敏且限长的异常摘要和 traceback，并与同一 `request_id` 关联。HTTP 响应仍只返回稳定错误码、通用消息、`request_id` 和是否可重试，不把底层异常、Dify Key、Dataset ID 或响应正文返回给调用方。不得在全局处理器中自动展开所有 `ServiceError` 原因。

## 5. 隐私与保留

禁止记录用户完整问题、AI 完整回答、真实用户 ID、上传文件内容、原始敏感文件名、Cookie、Authorization、`X-Admin-Token`、内部 Token、Dify Key、数据库/Redis URL。允许保存匿名用户哈希、资源 ID、错误码、字段长度、远端 HTTP 状态和脱敏摘要。

事件表默认保留 30 天；stdout 保留期由服务器日志策略确定。导出或截图前再次脱敏。任何发现密钥进入日志的情况均按安全事件处理并轮换密钥。

## 6. 后台日志接口与页面

- `GET /internal/v1/admin/logs`：按时间、等级、组件、事件代码、状态、request ID、资源 ID 分页筛选。
- `GET /internal/v1/admin/logs/{log_id}`：返回白名单详情；不存在返回 404。
- Streamlit 显示最近错误数、失败任务、操作/错误切换、筛选、分页和关联 ID。
- 测试页的结构化 HTTP 失败只显示 method、path、status、API code/message 和 `request_id`，不渲染响应正文、headers、内部完整 URL 或 Python traceback；运维人员用 `request_id` 到日志页查询脱敏根因。
- 页面仅监听服务器回环地址，经 SSH 隧道或受保护反向代理访问；普通 `INTERNAL_API_TOKEN` 无权读取。

## 7. 监控与告警建议

首版至少对连续摘要失败、清洗补偿失败、点击落库失败、外部删除积压、健康检查失败和 5xx 激增设置告警。告警只含事件 ID、组件、错误码、版本和时间，不含正文或密钥。
