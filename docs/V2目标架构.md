## 3. 分层约束

- `main.py` 只装配应用，不包含业务 SQL、Redis 或 Dify 流程。
- Router 处理协议、鉴权、校验和响应转换，调用 Service。
- Service 实现事务和业务规则，不依赖 FastAPI 或 Streamlit。
- Integration 隔离远端协议，提供超时、错误映射和可测试接口。
- Persistence 定义模型、查询和事务辅助，不反向依赖 Router。
- Worker Task 只做调度、租约和重试，核心逻辑调用 Service。
- UI 只调用公开或内部 API，不直连数据库、Redis 或 Dify。

允许依赖方向：`api/ui/workers → services → persistence/integrations`。禁止反向依赖和跨层循环引用。

## 4. 迁移顺序

1. 为当前 API、SSE、任务名和 CLI 增加特征测试。
2. 创建新包和适配层，先移动无副作用模型与工具。
3. 按商业会话、课程、清洗、运维顺序逐域迁移。
4. 保留旧导入路径的薄兼容导出，直到调用方和测试全部迁移。
5. 最后缩减旧聚合模块；每一阶段公开响应和任务名保持兼容。

任何目标结构项只有在代码、测试和运行验证均存在后，才能同步写入“项目目录结构”的当前状态。
