# AI 管理服务 V2 决策记录

> 状态：生效中（项目稳定决策的最高仓库基线）  
> 生效日期：2026-07-27  
> 适用范围：AI 管理服务、Dify 应用与知识库、测试 UI、课程发布、文档清洗和服务器验证。

## 1. 基线声明

以下计划和审计文件仅作为历史资料，不再直接指导开发；其中与本文或其他当前规范冲突的内容一律以最新 ADR 为准：

- `AI 管理服务完整开发执行计划.md`（P1）
- `AI管理服务快速落地与测试计划.md`（P2）
- `AI管理服务执行计划符合性审计报告.md`（审计输入，不是需求规格）

`AI管理服务当前状态与后续测试交接.md` 只作为滚动运行事实和开放事项入口；其中标记为历史的旧章节不指导新开发，也不覆盖需求和 ADR。

仓库文档的优先顺序为：用户当前明确确认并写入本文的最新 ADR → 本决策记录 → `V2需求规格说明.md` → `V2产品流程与边界.md` → `V2服务开发与数据设计.md` → 当前专项规范与运行手册 → 当前状态事实 → 日期化证据 → 历史资料。发现冲突时必须先更新决策记录或明确适用范围，禁止由代码、运行现状或口头转述隐式改变需求。

## 2. 已冻结决定

| ID | 决定 | 理由与影响 |
|---|---|---|
| ADR-001 | 不推倒重写，在现有 FastAPI、SQLAlchemy、Celery、Dify 和测试骨架上重构。 | 降低重新引入缺陷的风险；重构前先补特征测试。 |
| ADR-002 | 先完成 V2 需求、流程、静态 Demo 和设计，再改业务代码。 | 静态 Demo 用于产品确认；Streamlit 仅用于集成测试和内部运维。 |
| ADR-003 | 用户入口固定为商业顾问、朋友圈、写作三个；不设独立课程入口。 | 课程仅由商业顾问在合适场景推荐。 |
| ADR-004 | 商业会话由本服务保存；Dify Memory 关闭；每轮动态传摘要、游标后有限历史、画像、路线进度和当前问题。 | 避免双重记忆、上下文重复和不可控增长。 |
| ADR-005 | 一个本地逻辑会话按自然日对应一个 Dify 会话段。 | 支持跨日续聊，同时便于 7 天历史与远端会话清理。 |
| ADR-006 | 原始消息默认保留 7 天；只有确认已摘要的内容才可删除。 | 摘要失败、输出无效或游标冲突时禁止删除消息。 |
| ADR-007 | 课程发布首版继续使用 CLI `dry-run/publish`，不开发课程管理后台或 validation-batches API。 | 历史首版决定；课程/路线管理页发布能力已由 ADR-020 替代。 |
| ADR-008 | 课程点击主指标是链接点击总次数（PV）；同时保留匿名点击人数（UV）作为辅助指标。 | 每次有效签名跳转计 1 次点击；点击不代表完成课程。 |
| ADR-009 | 点击按课程、自然日汇总，不保存逐次点击明细。 | 满足次数统计；降低隐私、存储和日志风险。Redis 同时损坏时可能少计，属已接受限制。 |
| ADR-010 | 后台可查看必要操作和错误事件；完整调试日志输出结构化 JSON 到 stdout。 | 事件表不保存对话正文、密钥、真实用户 ID 或敏感文件内容。 |
| ADR-011 | 后台日志和统计接口使用独立 `X-Admin-Token`；Streamlit 仅绑定服务器回环地址。 | 将运维权限与普通内部调用权限隔离。 |
| ADR-012 | 清洗默认限制为单文件 50MB、每批最多 10 个、总计不超过 500MB。 | 历史默认值；单文件限制已由 ADR-019 替代。 |
| ADR-013 | Redis 缓存可回源数据库；分布式会话锁不可降级为多进程无效的内存锁。 | Redis 不可用时，涉及会话状态写入的请求返回可重试错误。 |
| ADR-014 | 服务器采用当前实例原地更新测试，使用不可变镜像、备份和明确回滚点；禁止容器内热改代码。 | 每次修复均在本地完成、测试、构建新镜像后重新部署。 |
| ADR-015 | V2 取代 P1/P2/H 作为当时唯一有效基线；旧资料保留但不删除。 | 保留审计链，同时避免多套计划并行生效。关于 H 的当前用途已由 ADR-016 部分替代。 |
| ADR-016 | 项目指令、文档索引、动态状态和日期化证据分层维护。根 `AGENTS.md` 只放稳定规则与导航；`docs/README.md` 维护权威和功能映射；当前状态保存滚动事实；每轮验收/排坑保存历史证据。 | 避免每次全局扫描和上下文膨胀，同时保持事实可追溯。ADR-015 中的 H 改为“顶部当前事实有效、旧章节历史”，P1/P2 仍为历史。 |
| ADR-017 | 原文件名可在管理员鉴权保护的 jx 清洗记录和 Dify 管理端显示；拆分名为 `原文件名主体__NNN.原扩展名`。原文件名、管理名和真实身份不得进入公开回答、SSE 引用、历史消息、普通日志或脱敏报告。 | 管理可辨识性与公开隐私分层处理；替代“所有敏感策略远端名称必须匿名”的旧口径。 |
| ADR-018 | 正式 Dify 数据只允许按精确 document ID、明确测试标记或本服务关联记录删除；仅凭名称正则不足以授权删除。整库清 Redis 还必须证明目标 DB 为本服务独占且已完成可恢复备份。 | 降低误删正式资料和共享缓存的风险。 |
| ADR-019 | 清洗默认限制为单文件 200MB、每批最多 10 个、总计不超过 500MB。 | 追认当前配置、环境示例、已发布实现和验收口径；替代 ADR-012 的 50MB 单文件默认值。 |
| ADR-020 | 课程与路线保留 CLI `dry-run/publish`，同时支持管理员清洗页通过 `course_information` / `learning_route` 策略发布；两条入口必须复用同一校验、远端验证、数据库事务和补偿规则。 | 追认当前已部署并验收的管理能力；替代 ADR-007 的“仅 CLI 发布”，但仍不建设通用课程 CRUD 后台。 |
| ADR-021 | 管理会话审计保存并展示原始 `user_id`，内部 `user_hash` 仅保留为隔离和关联键；会话列表使用最近一条助手消息的推荐课程、专业见解、推荐理由、token 消耗和响应耗时，详情按消息提供同一组字段。测试页保存服务端返回的本地 `conversation_id`，直到用户新建会话或切换用户。 | 满足管理员可追溯性和性能审计，同时不把内部哈希暴露给管理人员；历史未记录原始 ID 的记录保持空值，旧 `expert_insight` 只读兼容，不重新生成。 |
| ADR-022 | 文档模型任务采用 Batch/实时双通道；`BAILIAN_BATCH_ENABLED` 默认开启以保持既有阈值行为，关闭时仅让新任务走实时 Worker，已经创建的任务保持数据库中记录的模式。Batch 与实时分别保存价格版本、有效期和单价快照，实时模式不套用 Batch 折扣，仍受 RPM/TPM 与 Worker 并发限制。 | 降低测试等待时间而不改变在途任务或费用口径；价格快照缺失、过期或与实际调用模式不匹配时，课程自动路径不得入队。 |
| ADR-023 | `course_route_catalog` 默认采用“确定性结构解析→模型语义补全→价格/契约/隐私/Dify 回读门禁→同源原子发布”；名称、链接、稳定 ID、路线归属和顺序不能由模型选择。`COURSE_CATALOG_AUTO_PUBLISH=false` 时才启用结构审核表和语义审核表人工回退路径，未确定最终名称不得批准发布。 | 兼顾无歧义目录的低延迟导入和冲突目录的人工控制；任一门禁失败都不发布部分课程/路线，普通名称冲突不能靠模型猜测。 |
| ADR-024 | 同名或同内容任一命中都阻止重新入库；文件以 `excluded/duplicate_noop` 留下可审计记录。只有管理员按精确源文件 ID 和完整原文件名删除全部远端分片，并确认 `source_deleted_at`、`dedupe_released_at` 与批次聚合收敛后，才允许重新上传。 | 防止重传产生重名或重复知识；禁止按名称模糊删除、只删单个 Dify 文档或直接改库释放保护。 |
| ADR-025 | PDF/DOCX 转换后的“策略处理前 Markdown”是测试服务器诊断产物，由 `SAVE_CONVERSION_MARKDOWN` 独立控制；API 与清洗 Worker 使用专用共享目录，默认保留 7 天，生产环境禁止开启且不提供 HTTP 下载。 | 便于测试期定位版面/标题/表格转换问题，同时避免把可能未脱敏的中间正文变成正式资产或公共接口。 |
| ADR-026 | 百炼 Batch 默认关闭（`BAILIAN_BATCH_ENABLED=false`）；除非显式开启，否则新文档模型任务走实时 Worker，已有任务保留创建时模式。 | 测试等待时间过长会阻塞验收；实时模式仍受 RPM/TPM、并发和独立价格快照门禁约束。替代 ADR-022 中“默认开启”的口径。 |
| ADR-027 | 本轮清洗页必须验收六种指定策略：`personal_business_consultation`、`wechat_public_account_cognition`、`zsxq_post`、`xiaobot_post`、`lead_magnet`、`course_route_catalog`；`course_information`、`learning_route` 仅保留后端兼容，不在页面展示或本轮页面验收；既有 `book` 能力保持独立。 | 合并课程与路线入口，避免同一业务有两套可选策略；历史批次和接口兼容不因页面隐藏而破坏。 |

## 3. 明确不做

- 不建设面向最终用户的 Web 管理后台；Streamlit 不是正式产品界面。
- 不保存逐次课程点击事件，不用点击自动推进学习路线。
- 不让朋友圈和写作入口保存业务会话历史。
- 不允许模型直接生成或替换课程正式链接。
- 不在 V2 首版引入动态清洗策略平台、LLM Judge 平台或复杂发布审批系统。
- 不自动执行生产发布、Dify 写入或 Git push；均需对应授权和运行手册门禁。

## 4. 变更规则

任何影响入口、会话记忆、数据保留、课程发布、点击口径、权限或服务器拓扑的变更，都必须：

1. 新增 ADR 编号，写明替代的旧决定；
2. 同步更新需求、流程、设计和验收用例；
3. 给出数据迁移、兼容与回滚方案；
4. 通过评审后再实施。
