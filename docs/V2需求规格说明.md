# AI 管理服务 V2 需求规格说明

> 状态：V2 唯一需求基线  
> 关联文件：`V2决策记录.md`、`V2产品流程与边界.md`、`V2测试与验收规范.md`  
> 说明：P1、P2、H 均为历史资料；审计报告只提供问题线索，不替代本规格。

## 1. 目标与角色

V2 在保留现有服务能力的基础上，完成需求收敛、模块化重构、正确性修复、运维日志、课程点击统计和服务器验证，使项目达到可维护、可追踪、可回滚和可验收状态。

角色：

- **普通用户**：通过小程序或可信前端使用三个 AI 入口。
- **内部运营/测试人员**：通过受保护的 Streamlit 页面验证会话、课程、清洗、点击和日志。
- **发布人员**：通过 CLI 发布课程与路线，通过运行手册部署服务。
- **系统管理员**：配置 Token、数据库、Redis、Dify，执行备份、回滚和故障处置。

## 2. 功能需求

### 2.1 入口与会话

| ID | 需求 | 验收条件 |
|---|---|---|
| FR-ENT-001 | 系统只提供商业顾问、朋友圈、写作三个入口。 | 入口配置与静态 Demo 无第四个课程入口。 |
| FR-CONV-001 | 商业顾问支持新建、多会话列表、续聊、重命名、删除、反馈和停止生成。 | 不同匿名用户相互隔离；生命周期接口与 SSE 用例通过。 |
| FR-CONV-002 | 朋友圈和写作以无状态 Workflow 运行，不建立历史会话。 | 请求完成后不产生 `business_conversation` 数据。 |
| FR-CONV-003 | 商业会话在本地持久化，Dify Memory 关闭。 | 第二轮请求只包含本服务构建的动态上下文，无 Dify 重复记忆。 |
| FR-CONV-004 | 本地逻辑会话每日创建或复用一个 Dify 会话段。 | 同日复用、跨日新建；本地会话 ID 不变。 |
| FR-CONV-005 | 上下文仅查询摘要游标后的最近最多 50 条有效消息，并受字符预算限制。 | SQL 不加载整段历史；超长历史仍满足数量与字符上限。 |
| FR-CONV-006 | 摘要按顺序分批，成功后原子推进游标。 | 摘要失败、无效输出或游标竞争时不删除原消息。 |
| FR-CONV-007 | 原始消息默认保留 7 天。 | 清理仅删除已被摘要覆盖的数据；失败项记录事件并重试。 |
| FR-CONV-008 | 画像和路线进度只依据明确用户证据更新。 | 猜测、点击链接和模型自述不改变已确认事实。 |

### 2.2 课程、路线与点击

| ID | 需求 | 验收条件 |
|---|---|---|
| FR-COURSE-001 | 课程和路线通过 CLI 执行校验与发布。 | `dry-run` 输出课程/路线数量、警告、错误、能力判断、待停用项和目标 Dataset；错误数据不得发布。 |
| FR-COURSE-002 | 推荐模型只能给候选 ID，服务端校验启用、审核和路线状态并生成签名链接。 | 错误、停用、未审核 ID 不产生课程卡片或正式链接。 |
| FR-COURSE-003 | 新目录中消失、停用或未审核的课程/路线必须与 Dify 文档对账。 | 发布后旧文档不再被检索或推荐；补偿失败有可重试任务和日志。 |
| FR-COURSE-004 | 每次有效 `/r/{token}` 课程跳转增加该课程当日点击次数 1。 | 连续点击 N 次，PV 增加 N；过期/无效签名不计数。 |
| FR-COURSE-005 | 统计每日 PV 和匿名 UV，并长期保存每日汇总。 | 后台可按课程、日期查询每日值、区间累计值、排行和未落库实时值。 |
| FR-COURSE-006 | 点击不推进路线进度。 | 仅明确确认/完成证据可改变路线状态。 |

### 2.3 工具与清洗

| ID | 需求 | 验收条件 |
|---|---|---|
| FR-TOOL-001 | 朋友圈请求使用强类型字段：`request`、`source_material`、`audience`、`tone`、`constraints`。 | 未知字段按接口契约拒绝；长度限制与 DSL 一致。 |
| FR-TOOL-002 | 写作请求使用强类型字段：`request`、`source_text`、`audience`、`tone`、`format`、`constraints`。 | 同上。 |
| FR-CLEAN-001 | 清洗支持批量上传、逐文件状态、一次自动重试和人工重试。 | 部分失败不影响同批已成功文件；状态和失败阶段可查询。 |
| FR-CLEAN-002 | 默认单文件不超过 50MB，每批最多 10 个且总计不超过 500MB。 | 边界值、超限和组合限制测试通过。 |
| FR-CLEAN-003 | 上传校验扩展名、MIME、文件头、路径和可解码性。 | 伪扩展名、路径穿越、二进制伪文本、错误 DOCX/PDF 被拒绝。 |
| FR-CLEAN-004 | Dify 入库需确认索引完成、非零分块和 Metadata；失败执行补偿。 | 成功、零分块、超时、补偿成功/失败均有确定状态和事件。 |

### 2.4 日志与内部运维

| ID | 需求 | 验收条件 |
|---|---|---|
| FR-LOG-001 | 所有服务输出结构化 JSON 日志并携带 request ID、组件、版本、耗时和结果。 | API、Worker、Scheduler 的样例日志可按 request/task ID 关联。 |
| FR-LOG-002 | 必要操作和错误写入 `system_event_log`，默认保留 30 天。 | 会话删除、反馈、课程发布、清洗重试、补偿、夜间任务和未处理错误可查。 |
| FR-LOG-003 | 日志不得保存正文、真实用户 ID、密钥、Token、数据库口令或原始敏感文件名。 | 自动脱敏测试和人工抽检均无敏感值。 |
| FR-ADMIN-001 | 日志和课程点击管理接口使用独立 `X-Admin-Token`。 | 缺失、错误或普通内部 Token 均返回拒绝。 |
| FR-ADMIN-002 | Streamlit 提供日志、课程点击、清洗和测试页面。 | 固定绑定回环地址；临时外部测试经 Dify 已有 Nginx 路径转发，不新增端口或云安全组规则；支持筛选、分页、详情和 request ID 关联。 |

## 3. 非功能需求

| ID | 要求 |
|---|---|
| NFR-SEC-001 | 外部用户使用服务端 HMAC 匿名标识；管理 Token、内部 Token、Dify Key 不得出现在仓库或报告。 |
| NFR-CON-001 | 同一会话同时只允许一个生成任务；锁需 token 校验与续租。Redis 锁不可用时写请求 fail-closed。 |
| NFR-REL-001 | API、Worker、Scheduler 使用同一不可变镜像；异步任务可重试且副作用幂等。 |
| NFR-PERF-001 | 20 个不同会话持续 10 分钟；服务发出首个 SSE 状态事件的自身开销 p95 小于 200ms，不含模型生成时间。 |
| NFR-OBS-001 | 健康检查区分进程存活和依赖就绪；错误有稳定事件代码。 |
| NFR-DEP-001 | 服务器发布前必须完成备份验证、迁移评审和回滚点记录；服务器内禁止热改。 |
| NFR-MAIN-001 | `main.py` 仅装配应用，路由不直接承载复杂 SQL、Redis 或 Dify 逻辑；启动入口保持 `ai_management.main:app` 兼容。 |

## 4. 交付与完成定义

需求完成必须同时满足：代码已实现、自动测试通过、目标服务器真实链路通过、缺陷已关闭或明确接受、备份恢复与应用回滚已演练、证据已脱敏保存。仅有代码、文档或历史口头声明均不算完成。
