# 三类 AI 顾问消息操作 curl 测试命令

> 用途：在 jx 服务器或能访问 AI 管理服务私网地址的 Linux 主机上，验证商业顾问、朋友圈顾问和日常写作本次新增或变更的消息操作接口。
>
> 对应接口说明：[三类 AI 顾问消息操作接口变动说明](变动-顾问消息操作接口文档-20260909.md)。
>
> 只使用合成用户和合成短文本。不要把 Token、真实用户信息、正式业务内容或完整生成正文写入命令历史、报告或聊天。

## 1. 测试前准备

以下命令要求 Bash、`curl` 和 `jq`。默认使用 jx 私网地址；如果从其它受控主机调用，请在执行前设置正确的 `BASE_URL`。

```bash
set -u
umask 077

export BASE_URL="${BASE_URL:-http://172.30.157.197:8000}"
export USER_ID="advisor-actions-curl-$(date +%Y%m%d%H%M%S)-$$"
export RUN_DIR="$(mktemp -d /tmp/advisor-actions-curl.XXXXXX)"

# 交互输入内部令牌，不把令牌明文写入命令历史。
read -rsp "X-Internal-Token: " INTERNAL_TOKEN
printf '\n'
export INTERNAL_TOKEN

command -v curl >/dev/null || { echo "curl is required" >&2; exit 1; }
command -v jq >/dev/null || { echo "jq is required" >&2; exit 1; }

COMMON_HEADERS=(
  -H "X-Internal-Token: ${INTERNAL_TOKEN}"
  -H "X-User-Id: ${USER_ID}"
)

# 从 SSE 文件中读取 data JSON；不会打印正文。
sse_json() {
  sed -n 's/^data: //p' "$1" | tr -d '\r'
}

sse_last_terminal() {
  sse_json "$1" \
    | jq -c 'select(.status == "completed" or .status == "stopped" or .status == "failed")' \
    | tail -n 1
}

sse_last_message_id() {
  sse_json "$1" \
    | jq -r 'select((.status == "completed" or .status == "stopped") and .message_id != null) | .message_id' \
    | tail -n 1
}

sse_last_conversation_id() {
  sse_json "$1" \
    | jq -r 'select((.status == "completed" or .status == "stopped") and .conversation_id != null) | .conversation_id' \
    | tail -n 1
}

wait_for_task_id() {
  local file="$1"
  local task_id=""
  local attempt
  for attempt in {1..200}; do
    if test -s "$file"; then
      task_id="$(sse_json "$file" \
        | jq -r 'select(.code == "task_started") | .task_id // empty' 2>/dev/null \
        | tail -n 1)"
      if test -n "$task_id"; then
        printf '%s\n' "$task_id"
        return 0
      fi
    fi
    sleep 0.1
  done
  return 1
}

printf 'USER_ID=%s\nRUN_DIR=%s\n' "$USER_ID" "$RUN_DIR"
```

不要执行 `env`、`printenv`、`set` 或读取 `.env`，避免把其它密钥输出到终端。所有后续命令应在同一个 Bash 会话内执行。

## 2. 健康检查与入口能力

### 2.1 健康检查

```bash
curl --fail-with-body --silent --show-error \
  "${BASE_URL}/health/ready" \
  | jq '{status, checks}'
```

预期：HTTP `200`，`status=ready`；数据库、Redis 和 Dify 检查均正常。

### 2.2 检查三个入口的能力字段

`entry-config` 只需要内部服务令牌，不要求 `X-User-Id`。

```bash
curl --fail-with-body --silent --show-error \
  -H "X-Internal-Token: ${INTERNAL_TOKEN}" \
  "${BASE_URL}/internal/v1/entry-config" \
  | jq '.entries[] | select(.code == "business_advisor" or .code == "moments_advisor" or .code == "writing_advisor") | {code,history,feedback,regenerate,stop}'
```

预期：

```json
{"code":"business_advisor","history":true,"feedback":true,"regenerate":true,"stop":true}
{"code":"moments_advisor","history":false,"feedback":true,"regenerate":true,"stop":true}
{"code":"writing_advisor","history":false,"feedback":true,"regenerate":true,"stop":true}
```

## 3. 商业顾问重新生成

### 3.1 先生成一条合成商业顾问消息

```bash
export BUSINESS_INITIAL_SSE="${RUN_DIR}/business-initial.sse"

curl --fail-with-body --silent --show-error --no-buffer \
  "${COMMON_HEADERS[@]}" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -X POST \
  "${BASE_URL}/internal/v1/business/chat" \
  --data '{"query":"合成接口测试：请给出三条提升虚构门店复购率的通用建议。","conversation_id":null}' \
  >"${BUSINESS_INITIAL_SSE}"

export BUSINESS_CONVERSATION_ID="$(sse_last_conversation_id "${BUSINESS_INITIAL_SSE}")"
export BUSINESS_MESSAGE_ID="$(sse_last_message_id "${BUSINESS_INITIAL_SSE}")"

test -n "${BUSINESS_CONVERSATION_ID}" || { echo "business conversation_id missing" >&2; exit 1; }
test -n "${BUSINESS_MESSAGE_ID}" || { echo "business message_id missing" >&2; exit 1; }

printf 'business terminal: '
sse_last_terminal "${BUSINESS_INITIAL_SSE}" | jq '{conversation_id,message_id,task_id,status}'
```

预期：终态为 `completed`，得到本地 `BUSINESS_CONVERSATION_ID` 和本地 `BUSINESS_MESSAGE_ID`。

### 3.2 检查 `can_regenerate`

```bash
curl --fail-with-body --silent --show-error \
  "${COMMON_HEADERS[@]}" \
  "${BASE_URL}/internal/v1/business/conversations/${BUSINESS_CONVERSATION_ID}/messages?limit=20" \
  | jq --arg id "${BUSINESS_MESSAGE_ID}" '.items[] | select(.message_id == $id) | {message_id,role,status,can_regenerate}'
```

预期：目标消息 `role=assistant`、`can_regenerate=true`。

### 3.3 商业顾问重新生成成功

```bash
export BUSINESS_REGEN_SSE="${RUN_DIR}/business-regenerate.sse"

curl --fail-with-body --silent --show-error --no-buffer \
  "${COMMON_HEADERS[@]}" \
  -H "Accept: text/event-stream" \
  -X POST \
  "${BASE_URL}/internal/v1/business/messages/${BUSINESS_MESSAGE_ID}/regenerate" \
  >"${BUSINESS_REGEN_SSE}"

export BUSINESS_REGEN_MESSAGE_ID="$(sse_last_message_id "${BUSINESS_REGEN_SSE}")"

printf 'business regenerate terminal: '
sse_last_terminal "${BUSINESS_REGEN_SSE}" | jq '{conversation_id,message_id,dify_message_id,task_id,status}'

test "${BUSINESS_REGEN_MESSAGE_ID}" = "${BUSINESS_MESSAGE_ID}" \
  && echo "PASS: commercial local message_id was reused" \
  || { echo "FAIL: commercial local message_id changed" >&2; exit 1; }

BUSINESS_AFTER_REGEN_RESPONSE="$(curl --fail-with-body --silent --show-error \
  "${COMMON_HEADERS[@]}" \
  "${BASE_URL}/internal/v1/business/conversations/${BUSINESS_CONVERSATION_ID}/messages?limit=20")"

printf '%s' "${BUSINESS_AFTER_REGEN_RESPONSE}" \
  | jq -e --arg id "${BUSINESS_MESSAGE_ID}" \
    '(.items | length) == 2 and (.items[-1].message_id == $id) and (.items[-1].can_regenerate == true)' \
  >/dev/null \
  && echo "PASS: regenerate replaced the original pair without adding messages" \
  || { echo "FAIL: business message count or regenerated ID is inconsistent" >&2; exit 1; }
```

预期：

- 终态为 `completed`；
- 本地 `message_id` 与重新生成前完全相同；
- `dify_message_id` 为本次新生成的远端消息 ID；
- 商业消息数量不会因为重新生成增加。

自动检查字段、顺序和重新生成资格：

```bash
jq -e \
  --arg old "${BUSINESS_MESSAGE_ID}" \
  --arg latest "${BUSINESS_LATEST_MESSAGE_ID}" \
  '
    (.items | length) == 4
    and (.next_cursor == null)
    and ([.items[].role] == ["user", "assistant", "user", "assistant"])
    and (.items[1].message_id == $old)
    and (.items[1].can_regenerate == false)
    and (.items[3].message_id == $latest)
    and (.items[3].can_regenerate == true)
    and (([.items[] | select(.can_regenerate == true)] | length) == 1)
    and (all(.items[];
      has("message_id")
      and has("role")
      and has("content")
      and has("status")
      and has("recommendation")
      and has("retriever_resources")
      and has("created_at")
      and has("can_regenerate")
    ))
  ' \
  "${BUSINESS_MESSAGES_FILE}" \
  >/dev/null \
  && echo "PASS: complete multi-message response and can_regenerate rules" \
  || { echo "FAIL: multi-message response is incomplete or out of order" >&2; exit 1; }
```

### 3.5 验证 `next_cursor` 分页

使用 `limit=2` 读取第一页：

```bash
export BUSINESS_PAGE1_FILE="${RUN_DIR}/business-page-1.json"
export BUSINESS_PAGE2_FILE="${RUN_DIR}/business-page-2.json"

curl --fail-with-body --silent --show-error \
  "${COMMON_HEADERS[@]}" \
  "${BASE_URL}/internal/v1/business/conversations/${BUSINESS_CONVERSATION_ID}/messages?limit=2" \
  >"${BUSINESS_PAGE1_FILE}"

export BUSINESS_NEXT_CURSOR="$(jq -r '.next_cursor // empty' "${BUSINESS_PAGE1_FILE}")"
test "$(jq '.items | length' "${BUSINESS_PAGE1_FILE}")" -eq 2 \
  || { echo "first page should contain 2 messages" >&2; exit 1; }
test -n "${BUSINESS_NEXT_CURSOR}" \
  || { echo "first page next_cursor missing" >&2; exit 1; }

jq '{items:[.items[] | {message_id,role,can_regenerate}],next_cursor}' \
  "${BUSINESS_PAGE1_FILE}"
```

把第一页返回的 `next_cursor` 原样传给第二页：

```bash
curl --fail-with-body --silent --show-error --get \
  "${COMMON_HEADERS[@]}" \
  --data-urlencode 'limit=2' \
  --data-urlencode "cursor=${BUSINESS_NEXT_CURSOR}" \
  "${BASE_URL}/internal/v1/business/conversations/${BUSINESS_CONVERSATION_ID}/messages" \
  >"${BUSINESS_PAGE2_FILE}"

jq -e \
  --arg latest "${BUSINESS_LATEST_MESSAGE_ID}" \
  '(.items | length) == 2
   and (.next_cursor == null)
   and (.items[-1].message_id == $latest)
   and (.items[-1].can_regenerate == true)' \
  "${BUSINESS_PAGE2_FILE}" \
  >/dev/null \
  && echo "PASS: next_cursor pagination returned the second page" \
  || { echo "FAIL: second page or next_cursor is inconsistent" >&2; exit 1; }

jq '{items:[.items[] | {message_id,role,can_regenerate}],next_cursor}' \
  "${BUSINESS_PAGE2_FILE}"
```

预期：第一页和第二页各 2 条消息；第一页 `next_cursor` 非空，第二页 `next_cursor=null`；两页消息均按时间从早到晚排列。

### 3.6 商业顾问重新生成停止

本节只停止本测试刚启动的合成重新生成任务，不会扫描或停止其它任务。

```bash
export BUSINESS_STOP_SSE="${RUN_DIR}/business-regenerate-stop.sse"

curl --fail-with-body --silent --show-error --no-buffer \
  "${COMMON_HEADERS[@]}" \
  -H "Accept: text/event-stream" \
  -X POST \
  "${BASE_URL}/internal/v1/business/messages/${BUSINESS_LATEST_MESSAGE_ID}/regenerate" \
  >"${BUSINESS_STOP_SSE}" &
BUSINESS_STREAM_PID=$!

if BUSINESS_STOP_TASK_ID="$(wait_for_task_id "${BUSINESS_STOP_SSE}")"; then
  curl --fail-with-body --silent --show-error \
    "${COMMON_HEADERS[@]}" \
    -X POST \
    "${BASE_URL}/internal/v1/business/chat/${BUSINESS_STOP_TASK_ID}/stop" \
    | jq .
else
  echo "No business task_started received within 20 seconds" >&2
fi

wait "${BUSINESS_STREAM_PID}" || true
printf 'business stopped terminal: '
sse_last_terminal "${BUSINESS_STOP_SSE}" | jq '{conversation_id,message_id,task_id,status}'
```

预期：停止接口 HTTP `200`，原 SSE 终态为 `message_end.status=stopped`，并保留停止前已收到的新片段。如果模型在停止请求前已经结束，停止接口可能返回 `404 TASK_NOT_FOUND`；此时应重新执行本节，不能把已完成任务的 404 当作停止能力失败。

```bash
export WRITING_REGEN_SSE="${RUN_DIR}/writing-regenerate.sse"

curl --fail-with-body --silent --show-error --no-buffer \
  "${COMMON_HEADERS[@]}" \
  -H "Accept: text/event-stream" \
  -X POST \
  "${BASE_URL}/internal/v1/tools/writing/messages/${WRITING_MESSAGE_ID}/regenerate" \
  >"${WRITING_REGEN_SSE}"

export WRITING_NEW_MESSAGE_ID="$(sse_last_message_id "${WRITING_REGEN_SSE}")"
export WRITING_REGEN_CONVERSATION_ID="$(sse_last_conversation_id "${WRITING_REGEN_SSE}")"

test -n "${WRITING_NEW_MESSAGE_ID}" || { echo "new writing message_id missing" >&2; exit 1; }

  && echo "PASS: writing received a new opaque message_id" \
  || { echo "FAIL: writing message_id was not replaced" >&2; exit 1; }
test "${WRITING_REGEN_CONVERSATION_ID}" = "${WRITING_CONVERSATION_ID}" \

```

预期：两个工具都保持原本地 `conversation_id`，同时返回新的不透明 `message_id`。

## 8. 工具停止

本节启动一条新的合成朋友圈生成流，取得该流自己的 `task_id` 后立即停止。不会查找或停止其它正在运行的任务。

```bash
export MOMENTS_STOP_SSE="${RUN_DIR}/moments-stop.sse"

curl --fail-with-body --silent --show-error --no-buffer \
  "${COMMON_HEADERS[@]}" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -X POST \
  "${BASE_URL}/internal/v1/tools/moments/run" \
  --data "$(jq -n --arg id "${MOMENTS_CONVERSATION_ID}" \
    '{conversation_id:$id,inputs:{request:"合成停止测试：生成一篇较长的虚构新品介绍。",source_material:"仅用于接口停止测试。",audience:"测试受众",tone:"自然",constraints:"分十个部分详细展开"}}')" \
  >"${MOMENTS_STOP_SSE}" &
MOMENTS_STREAM_PID=$!

if MOMENTS_STOP_TASK_ID="$(wait_for_task_id "${MOMENTS_STOP_SSE}")"; then
  curl --fail-with-body --silent --show-error \
    "${COMMON_HEADERS[@]}" \
    -X POST \
    "${BASE_URL}/internal/v1/tools/${MOMENTS_STOP_TASK_ID}/stop" \
    | jq .
else
  echo "No moments task_started received within 20 seconds" >&2
fi

wait "${MOMENTS_STREAM_PID}" || true
printf 'moments stopped terminal: '
sse_last_terminal "${MOMENTS_STOP_SSE}" | jq '{conversation_id,message_id,task_id,status}'
```

预期：停止接口 HTTP `200`，原 SSE 终态为 `message_end.status=stopped`。如果生成在停止请求前已经完成，停止接口会返回 `404 TASK_NOT_FOUND`；重新执行本节即可。

重复停止同一 `task_id` 的探针：

```bash

  --output "${RUN_DIR}/repeat-stop.json" \
  --write-out 'HTTP %{http_code}\n' \
  "${COMMON_HEADERS[@]}" \
  -X POST \

```

预期：HTTP `404`，`code=TASK_NOT_FOUND`。

## 11. 结果判定

| 结果 | 判断 |
| --- | --- |
| 健康检查不是 HTTP 200 | 服务地址、网络或服务状态异常，先不要判断业务接口 |
| `entry-config` 缺少 `regenerate/stop/feedback` | 当前服务不是本次接口版本，或配置聚合异常 |
| 商业重生成后本地 `message_id` 改变 | 不符合商业顾问严格替换契约 |
| 商业重生成后消息数量增加 | 不符合覆盖原用户/助手二元组的严格替换契约 |
| 商业完整列表不是 `items + next_cursor` | 消息列表响应结构不符合接口文档 |
| 多轮商业消息不是从早到晚排列 | 分页顺序不符合 `created_at + message_id` 升序契约 |
| 旧助手消息 `can_regenerate=true` | 重新生成资格计算错误；只有最新符合条件的助手消息可以为 `true` |
| 第一页有更多消息但 `next_cursor` 为空 | 分页游标生成异常 |
| 原样回传 `next_cursor` 后没有得到下一页 | 分页游标读取或 URL 编码异常 |
| 工具重生成后 `message_id` 没有改变 | 不符合工具同会话新增一轮的契约 |
| 工具重生成后本地 `conversation_id` 改变 | Dify 会话或本地会话映射不符合契约 |
| SSE 没有 `task_started` | 无法在生成过程中取得可停止 `task_id` |
| SSE 出现 `error.status=failed` | 丢弃本轮全部增量，并按 `code/retryable/request_id` 排查 |
| 停止后为 `message_end.status=stopped` | 正常；保留已收到的片段 |
| 已结束或重复停止返回 `404 TASK_NOT_FOUND` | 正常，不要继续重试同一 `task_id` |
| 跨 kind 返回 `404 MESSAGE_NOT_FOUND` | 正常的归属隔离行为 |
| reset 后旧消息仍可反馈或重生成 | 不符合会话失效后的消息操作边界 |

测试报告只记录 HTTP 状态、错误码、终态和脱敏 ID。不要保存生成正文、原始 `query/inputs`、真实用户 ID 或内部 Token。
