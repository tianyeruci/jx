# Codex 项目上下文与文档维护规则

> 状态：当前有效  
> 适用范围：jx-now 仓库中的 Codex 项目指令、文档发现和变更同步  
> 最后核对：2026-07-30

## 1. 官方事实

以下为 OpenAI Codex 官方文档明确说明的行为：

1. Codex 在开始工作前读取 `AGENTS.md`。
2. 项目级发现从项目根目录向当前工作目录逐层进行；每层优先检查 `AGENTS.override.md`，再检查 `AGENTS.md`。
3. 越接近当前目录的指令越晚合并，因此可覆盖上层规则。
4. 空文件会被忽略。项目指令合并大小默认上限为 32 KiB。
5. 指令链通常在一次运行或一次 TUI 会话开始时建立；修改后应开启新运行或新会话核验。
6. 官方建议保持 `AGENTS.md` 小而精，只放持久项目规则；目录专用规则放到最近的目录。
7. 复杂、可复用并需要脚本或参考资料的流程更适合 Skill；格式、lint 等可机械检查的要求应交给 CI 或工具。

官方来源：

- [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md.md)
- [Codex customization](https://learn.chatgpt.com/docs/customization/overview.md)

这些是 Codex 产品的项目指令发现规则，不是某个 GPT-5.6 模型专属的提示词格式。GPT-5.6 会受当前会话、系统约束和 Codex 指令链共同影响，但仓库内的持久规则仍应放在最小合适的 Codex 层级。

## 2. 本项目采用的分层

| 信息 | 存放位置 | 原因 |
|---|---|---|
| 每次都应遵守的稳定项目规则 | 根 `AGENTS.md` | 自动加载，必须短小 |
| 子目录长期独立规则 | 最近的嵌套 `AGENTS.md` | 只影响对应子树 |
| 文档状态、用途、权威级别和阅读路由 | `docs/README.md` | 可按需读取，不占每次启动上下文 |
| 功能、接口和工程入口定位 | `docs/功能与接口索引.md` | 先按需定位；机械入口从源码静态生成并可检查过期 |
| 当前线上版本、数据状态、回滚点和开放事项 | 根“当前状态与后续测试交接” | 可直接更新的动态滚动事实；文末保留修改原因和前后差异 |
| 产品与架构决定 | `docs/V2决策记录.md` | 可审计、可编号、可替代 |
| API、清洗、部署等详细规则 | 对应专项规范/手册 | 由功能域按需读取 |
| 一轮发布的完整结果 | 日期化验收和排坑记录 | 保留历史证据，不覆盖旧轮次 |
| 原始运行报告 | `var/reports/` | 可能体积大或含受保护信息，不提交 |
| 可复用长流程 | `.agents/skills/` 或已有脚本 | 渐进加载，避免膨胀 `AGENTS.md` |

## 3. `AGENTS.md` 应写什么

只写满足至少一个条件的内容：

- 每个或大多数任务都会影响行为。
- 同类错误已经重复发生。
- 不写会造成数据、发布、隐私或兼容性风险。
- 能把新任务稳定路由到正确的文档、源码或测试。
- 是仓库特有且无法由通用上层指令推断的约定。

推荐表达方式：

- 使用可执行、可判断的短句。
- 给出安全路径或例外条件，不只写“禁止”。
- 链接权威入口，不复制长段规范。
- 将相关规则按“开始任务、权威顺序、验证、文档同步、安全”分组。
- 先用测试、lint、schema 或脚本机械执行，再把人工判断部分写入规则。

## 4. 不应写什么

- 当前镜像、版本号、服务器 IP、备份路径或一次测试数字。
- 单次任务计划、临时问题列表、完整故障过程或命令输出。
- 所有文档的摘要、所有源码目录树或大段接口契约。
- 可以由 formatter、lint、测试、CI 或 schema 自动检查的细枝末节。
- 只适用于个人的表达风格；这类内容应放在全局指令。
- 尚未确认、可能很快改变或只基于一次观察的推测。

## 5. 每次任务的最小读取流程

1. Codex 自动获得根 `AGENTS.md`。
2. 从 `docs/README.md` 和 `docs/功能与接口索引.md` 按功能、路径或入口定位当前域。
3. 只读取该域的权威需求、专项规范、相关源码和测试；接口、命令和任务不再依赖全仓搜索。
4. 需要判断线上事实时，再读取当前状态文档的最新区。
5. 需要复盘原因时，再打开最近的日期化验收或排坑记录。
6. 只有在跨域、索引过期、结构变化或文档冲突时才扩大搜索。

同一运行内已读取且未变化的文件不机械重读；新运行会重新加载 `AGENTS.md`。不能仅凭模型记忆判断文件未变化，必要时使用 Git 状态、时间或内容差异核验。

项目结构文档只维护可核验的顶层结构、关键入口、职责、数据流和测试映射，不复制完整文件清单。功能与接口索引把机械入口限制为已注册 Router、CLI、Worker、Compose、Dify 与指定脚本；它静态解析源码，不导入应用或加载环境配置。需要具体符号时再在命中的源码域内搜索，避免为了“掌握项目”而预加载整个仓库。

## 6. 写入前的澄清边界

- 对会实质改变任务范围、安全、权限、明显成本或不可逆结果的歧义，在写入前一次性列出并确认。
- 对不改变目标的次要歧义，采用安全、可逆且与现有实现一致的默认值，并在交付时说明。
- 可从仓库、配置、测试或当前状态发现的事实必须先只读核验，不能转交用户重复提供。
- 远端写入、生产变更、付费、提权、破坏性或不可逆操作仍需明确授权。

## 7. 变更后的文档更新

修改完成前执行一次影响检查：

1. 公开行为是否改变：更新接口、产品或清洗规范；HTTP 接口或工程入口变化时运行 `scripts/generate_project_index.py --write` 和 `--check`。
2. 数据、迁移或回滚是否改变：更新设计和运行手册。
3. 目录、入口或依赖方向是否改变：更新实际结构。
4. 测试命令、门槛或样本是否改变：更新测试指南。
5. 线上版本或数据状态是否改变：远端通过后更新当前状态。
6. 是否形成长期决定：新增或替代 ADR。
7. 是否出现可复用故障经验：补日期化排坑记录。

历史文档不做无差别同步。若旧文档仍可能误导执行，应在索引或文档顶部标记“历史/被替代”，并链接当前权威来源。

`AI管理服务当前状态与后续测试交接.md` 可在任务范围内直接维护，不需要把每次更新拆成新文件。每次修改完成后必须在该文档结尾追加一条记录，至少包含“修改原因”“修改前”“修改后”；记录描述事实变化和口径变化，不复制密钥、正文或其他敏感数据。

## 8. 维护和核验

- 每次修改 `AGENTS.md` 都检查是否可以删掉重复内容或改成链接。
- 根文件接近 8 KiB 时先审查拆分，不等待触及默认 32 KiB 上限。
- 只有出现真实子树差异时才新增嵌套文件，避免多层规则难以追踪。
- 新会话可要求 Codex说明已加载的指令来源，核对根文件与可能的嵌套覆盖。
- 文档索引新增、删除、重命名或权威状态变化时同步更新 `docs/README.md`。
- 功能与接口索引必须通过 `python scripts/generate_project_index.py --check`；不能用导入生产应用或读取密钥来生成文档。

## 9. 事实、推论和建议的表达

- **事实**：由代码、测试、运行结果、官方文档或原始资料直接支持。
- **推论**：由多个事实推导，必须说明推导条件和可能的替代解释。
- **建议**：在目标和约束下的取舍，必须说明主要收益、代价和适用条件。
- **不确定**：证据不足或来源可能过时，明确写出缺少什么证据以及如何验证。

发现用户或既有文档的前提与证据冲突时，应直接指出冲突、展示证据，并基于更可靠前提继续；不能为了保持表面一致而延续错误结论。
