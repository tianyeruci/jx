# V2 修改说明（2026-07-28）

> 本文用于代码交接时快速识别“本次改了什么、为什么改、是否已上线”。详细命令、证据与待验收项以 [V2本次缺口修复与服务器发布记录-2026-07-28.md](V2本次缺口修复与服务器发布记录-2026-07-28.md) 为准；Dify 实际联调故障与处理见 [V2 Dify 联调问题与修复记录](V2-Dify联调问题与修复记录-2026-07-28.md)。

## 已上线的修改

| 范围 | 修改 | 作用 |
| --- | --- | --- |
| 数据隔离 | AI 服务改用 Dify PostgreSQL 中独立 `ai_management` 数据库/角色、Dify Redis DB 5、`ai:` 前缀和独立 Celery 队列 | 不与 Dify 应用数据混用；旧 AI 独立卷保留作回滚，不挂载到 V2。 |
| 会话与 SSE | SSE 统一加入 `schema_version: "2.0"`、`request_id`、`sequence`；会话/消息使用 cursor 分页；保存显示名和反馈 | 小程序后端可稳定解析流并支持追踪、续聊与反馈。 |
| 上下文与维护 | 模型只用当前会话摘要、北京时间当天原始消息及已确认画像/路线；摘要任务加会话锁；清理改为北京时间 02:00 | 控制上下文膨胀，减少重复摘要，保留策略可管理。 |
| 路线与课程 | 路线确认、阶段确认、完成推进改为显式状态机；课程点击仍是每日 PV/UV 汇总 | 避免自动推进；满足“统计点击次数”而不保存逐次点击明细。 |
| AI 管理 API | 增加风格 Prompt、历史保留、两个固定知识库的文档/批次/启停/删除接口 | 常用 Prompt 与知识库操作可由受控管理端完成；所有写入均要求内部 Token + 管理员 Token。 |
| 知识库清洗 | 支持原样/清洗上传、文件安全校验、200 MB 单文件和 10/500 MB 批次限制；PDF 不启用 OCR；同名同哈希不重复索引、同名异内容延后替换旧文档 | 降低重复索引、异常文件和替换失败带来的数据风险。 |
| 日志与清理 | 必要操作/错误记录可由后台日志查询；用户 AI 数据删除保留课程每日 PV/UV | 支持运维追查与隐私清理。 |
| 临时测试页 | Streamlit 经现有 Dify Nginx `/ai-management-test/` 访问；页面仅提供用户链路测试和只读管理 | 不增加公网端口，也不在浏览器暴露管理写权限。 |

## 特别注意

1. 不得运行 `docker compose ... --remove-orphans`，因为遗留 AI PostgreSQL/Redis 容器和卷是回滚资产。
2. 不得清空 Dify PostgreSQL、Dify Redis 或 Dify Dataset；V2 已通过新 AI 库和 Redis DB 5 避免旧数据干扰。
3. `db_postgres` 与 `redis` 只能在 `docker_default` 网络使用。不要把 V2 服务重新接回遗留 AI 默认网络，否则可能解析到错误 Redis。
4. 三个用户 DSL 已重新导入并发布，且 AI 服务已同步当前应用访问 Key；但商业顾问的分类分支在汇合处引用未执行变量，属于 P0 DSL 结构问题，尚未修复/重新发布，不能当成商业顾问 Dify 全链路已通过。
5. 临时 Streamlit 页公开期间不要输入真实用户内容、文件或任何 Token；知识库写入 E2E 必须通过受控管理端补测。
