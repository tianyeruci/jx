# AI 管理服务当前项目目录结构

> 状态：当前实际结构（as-built）
> 最后核对：2026-08-03
> 目标结构另见 [V2 目标架构](V2目标架构.md)

本文只描述仓库当前存在且可核验的入口、职责和依赖。未来计划不得提前写成当前事实；精确 HTTP 接口和工程入口映射见[功能与接口索引](功能与接口索引.md)。

## 1. 顶层结构

```text
jx-now/
├─ ai_management/          # FastAPI 服务、领域逻辑、Worker、CLI 和 Streamlit 测试页
├─ knowledge_cleaner/      # 可复用文档识别、抽取、清洗、分块和 Dify 适配
├─ dify/
│  ├─ dsl/                 # 四个 Dify 1.13.3 应用 DSL
│  ├─ prompts/             # 四份独立 Prompt
│  └─ nginx/               # Dify/测试页代理配置
├─ migrations/             # Alembic 环境和只追加迁移
├─ scripts/                # 契约、验收、备份、清理、发布、RAG、OCR 按需启停和负载辅助
├─ tests/                  # 当前为扁平 pytest 测试集
├─ test_data/              # 合成课程、清洗、知识库、RAG 黄金集和错误样本
├─ docs/                   # 当前规范、运行手册、日期化验收和历史资料
├─ demo/                   # 不调用真实 API 的静态原型
├─ var/                    # 运行数据和原始报告，不提交
├─ docker-compose.ai.yml   # API、Worker、Scheduler、PostgreSQL、Redis
├─ docker-compose.ui.yml   # Streamlit 测试页
├─ Dockerfile*             # 在线/离线核心、UI 和 OCR 专用镜像
├─ deploy/systemd/         # jx OCR Worker 按需启停的 systemd service/timer
└─ pyproject.toml          # Python 包、依赖、测试和 Ruff 配置
```

`build/`、`dist*/`、`output/`、`tmp/`、wheelhouse、缓存、数据库、真实样本和运行报告是本地或发布产物，不属于源码结构。

## 2. `ai_management` 当前结构

```text
ai_management/
├─ main.py                 # FastAPI 创建、异常处理、路由装配
├─ api/routers/            # health、entry、business、tools、admin、knowledge
├─ ops/                    # 受控运维模块；当前含快速测试环境精确归零
├─ services/
│  ├─ admin_settings.py    # 管理配置
│  ├─ style_settings.py    # AI 风格配置
│  └─ observability/       # 事件与结构化日志
├─ workers/
│  ├─ celery_app.py        # Celery 装配
│  └─ tasks/               # cleaning、maintenance、summary
├─ config.py               # 环境配置与生产校验
├─ db.py / models.py       # SQLAlchemy 会话和当前聚合模型
├─ cache.py                # Redis 缓存、锁和短期状态
├─ dify.py                 # Dify App/Knowledge 调用
├─ conversations.py        # 商业会话、上下文、历史、摘要与反馈
├─ courses.py              # 课程、路线、推荐、签名跳转和点击
├─ course_import.py        # 课程/路线解析和发布
├─ cleaning.py             # 批次、文件、条目、复核和发布编排
├─ privacy.py              # 身份发现、别名和公开文本隐私处理
├─ stream_filter.py        # 跨 SSE 分片的受保护文本过滤
├─ schemas.py              # 当前聚合请求、响应和事件模型
├─ tasks.py                # 旧任务导入兼容层
├─ cli.py                  # 课程发布 CLI
├─ rag_eval.py             # RAG 评测
└─ test_ui.py              # Streamlit 测试与运维页
```

当前是“已开始分层但尚未完全拆分”的混合结构：路由、部分 Service 和 Worker 已形成目录，领域逻辑、模型、Schema、Dify 和 Redis 适配仍有聚合模块。不能把 `docs/V2目标架构.md` 中尚不存在的 `integrations/`、`persistence/`、细分 `schemas/` 或 `ui/pages/` 当成当前实现。

## 3. 主要入口

| 场景 | 入口 |
|---|---|
| FastAPI | `ai_management.main:app` |
| Celery Worker / Scheduler | `ai_management.workers.celery_app`，兼容入口 `ai_management.tasks.celery_app` |
| 课程/路线 CLI | `python -m ai_management.cli` |
| Streamlit 测试页 | `streamlit run ai_management/test_ui.py` |
| Alembic | `alembic.ini`、`migrations/env.py` |
| 本地测试 | `python -m pytest -q tests` |
| Dify 契约 | `scripts/dify_contract_check.py` |
| 发布前备份/清理 | `scripts/jx_prebaseline_backup.sh`、`scripts/jx_prebaseline_clean.sh` |
| 远端基线/发布 | `scripts/jx_current_baseline.sh`、`scripts/jx_deploy_release.sh` |
| 快速代码测试部署 | `scripts/jx_quick_deploy.sh`、`ai_management.ops.quick_reset` |
| 清洗/RAG 验收 | `scripts/jx_full_cleaning_baseline.sh`、`scripts/jx_rag_regression.py` |

命令参数、环境门禁和回滚方式以当前运行手册为准，不在结构文档复制。

需要按功能、路径、命令或任务名定位时，先查[功能与接口索引](功能与接口索引.md)，再读取命中的源码、测试和专项规范。

## 4. 当前数据流

### 4.1 业务聊天

```text
小程序后端 / 测试页
  → FastAPI Router（鉴权、协议）
  → conversations / courses / context
  → PostgreSQL（事实、历史、画像、目录）
  → Redis（锁、缓存、短期状态）
  → Dify App
  → privacy + stream_filter
  → SSE / JSON
```

### 4.2 文件清洗

```text
管理接口 / 测试页上传
  → cleaning（批次和状态）
  → Celery cleaning task
  → knowledge_cleaner（识别、抽取、策略、分块）
  → 本地预检和受保护 Metadata
  → Dify Knowledge 创建、索引、父子块和 Metadata 回读
  → 成功提交或同源补偿回滚
```

### 4.3 课程和路线

```text
Markdown 输入
  → course_import 校验
  → 远端子文档预检/发布
  → PostgreSQL 单事务提交课程和路线目录
  → business_advisor 检索与候选 ID 校验
  → 服务端签名 redirect_url
```

## 6. 依赖方向

当前期望方向：

```text
api / test_ui / workers
  → services 或领域模块
  → db/models/cache/dify/knowledge_cleaner
```

新代码不得增加 Router 直接写业务 SQL、UI 直连数据库/Dify、Persistence 反向依赖 Router 等耦合。对仍存在的旧聚合模块做局部修改时保持兼容，不借机无保护地大规模搬迁。

## 7. 版本库边界

应提交：

## 8. 更新触发器

出现以下变化时同步更新本文和 `docs/README.md`：

- 新增、删除或移动顶层目录。
- 改 FastAPI、Worker、CLI、测试页或发布入口。
- 改模块职责、依赖方向或主要数据流。
- 将目标架构中的一项真正落地并完成测试。
- 测试文件拆分或责任范围发生实质变化。
- HTTP 接口、CLI、Worker、Compose、Dify 或发布/RAG 脚本入口变化：更新“功能与接口索引”的自动区并通过其检查。

仅修改函数内部实现、文案或一次性脚本参数时，不机械改目录结构文档。
