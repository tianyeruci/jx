# jx 文档清洗本地状态归零失败恢复与脚本修复记录

日期：2026-08-02  
范围：旧版归零脚本预检失败、测试页 502、失败恢复修复和终态门禁修正

## 1. 现象与影响

用户先运行只读计划，结果包含 `7` 个 `completed`、`1` 个 `partially_completed` 和 `1` 个 `processing` 批次，`can_execute=false`。随后执行归零命令：

1. `test-ui` 被停止；
2. 前置捕获发现并非所有批次都为 `completed`，抛出 `RuntimeError`；
3. EXIT trap 读取已经离开函数作用域的局部变量，触发 `services_may_need_restart: unbound variable`；
4. `test-ui` 没有自动恢复，Nginx 因上游不可用返回 `502 Bad Gateway`。

失败发生在备份和删除步骤之前。本次没有删除 PostgreSQL 清洗记录、Redis 键、上传目录或 Dify 文档，不需要恢复数据库备份。

## 2. 根因

- 恢复状态 `services_may_need_restart` 和临时目录变量定义在 `execute_reset` 的局部作用域；`set -u` 下，shell 退出时 EXIT trap 已无法读取局部变量。
- 门禁只接受 `completed`，没有区分 `partially_completed` 的两种含义：它既可能是已取消模型任务后的终态，也可能是发布分片尚在排队的中间态。

孤儿容器警告不是根因，不得使用 `--remove-orphans` 处理本故障。

## 3. 修复

- 把 EXIT trap 所需的临时目录和服务恢复标记提升为脚本级变量；trap 先注销自身，再恢复服务、校验并清理固定目录下的临时路径，最后保留原退出码。
- 批次只接受 `completed`、`partially_completed`、`failed`、`review_required` 作为候选终态；同时检查文件、条目、模型任务和发布分片状态。任何活动子状态都会拒绝清除。
- 保留原有 Dify 文档删除任务门禁、完整备份、精确 Redis/上传目录范围和删除后健康验证。

## 4. 验证

- 新增 Bash EXIT trap 回归：模拟退出码 `7`，确认恢复函数执行、临时目录删除、退出码保持为 `7`，且无 `unbound variable`。
- `bash -n scripts/jx_reset_cleaning_local_state.sh` 通过。
- 清洗发布契约测试覆盖候选终态、各层终态集合、脚本级恢复状态和禁止 Dify 删除。
- 本轮不在 jx 执行新版清除；用户当前数据保留，仅提供测试页恢复命令。

## 5. 恢复命令

服务器只需重新启动测试页并验证 API/UI；命令见 [jx 文档清洗本地状态归零操作说明](jx文档清洗本地状态归零操作说明.md#31-预检失败后测试页出现-502)。
