## 2. 这次实际修了什么

### 2.1 知识库上传批次状态 / 重试 500

问题根因：

- `get_cleaning_batch()` 返回的数据里包含 `datetime`
- `cache.set_json()` 直接 `json.dumps(...)`
- 导致：

```text
TypeError: Object of type datetime is not JSON serializable
```

修复方式：

- 在 `ai_management/cache.py` 增加 `date` / `datetime` 的 JSON 序列化处理；
- 内存回退缓存也统一保存 JSON 归一化后的值，避免 Redis / 内存行为不一致。

修复结果：

- `GET /internal/v1/admin/knowledge-bases/{kb_code}/upload-batches/{batch_id}` 通过；
- `POST /internal/v1/admin/knowledge-bases/{kb_code}/upload-batches/{batch_id}/files/{file_id}/retry` 通过。

### 2.2 课程卡片 / 跳转 / 点击统计链路

问题根因：

- Dify 课程知识库已有 11 个课程/路线文档；
- 但本地 `Course` / `LearningRoute` 表为空；
- 服务端课程卡片校验依赖本地快照，不直接从 Dify 文档列表发卡片；
- 所以前一轮没有 `course_cards`，也就没有 `redirect_url`，整条点击链路无法验收。

处理方式：

- 使用临时脚本 `tmp/sync_test_catalog_local.py`
- 将 `test_data/courses/测试课程与路线.md` 中的合成测试课程目录同步到本地 `Course` / `LearningRoute` 表
- 只重建本地快照，不写 Dify，不删除 Dify 数据

修复结果：

- `GET /internal/v1/admin/catalog` 返回 `9` 门课程、`2` 条路线；
- 商业顾问课程问题会返回 `course_cards`；

- `GET /internal/v1/admin/course-clicks` 实测看到 PV/UV 递增。

## 5. 这次踩坑记录

### 5.1 Windows 本地 pytest 与 SQLite 文件锁

现象：

- `test_ai_management.db` 被残留 pytest 进程占用；
- 触发 `PermissionError` 或 `index already exists` 一类假故障。

这次处理：

- 不复用默认 `test_ai_management.db`
- 每次用独立 `TEST_DATABASE_PATH` 跑针对性 pytest

结论：

- 这是本地测试环境问题，不是业务代码回归。

### 5.2 RTK 的 pytest 包装层参数透传异常

现象：

- `rtk pytest tests/test_ai_management.py -k ...` 返回 `No tests collected`

这次处理：

- 回退到原生 `python -m pytest`

结论：

- 这次不是测试缺失，而是 RTK 包装层参数透传问题。

### 5.3 Windows here-string 通过 SSH 传 Bash 时混入 `\r`

现象：

- 远端 `docker tag` 标签尾部混入 `\r`
- 远端 `docker build ... .` 的上下文路径被识别成 `.\r`

这次处理：

- 关键远端发布命令改用单行 `ssh jx "..."` 执行
- 避免 here-string + SSH + Bash 的 CRLF 污染
