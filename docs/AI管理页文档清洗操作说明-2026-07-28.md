# AI 管理页文档清洗操作说明

更新时间：2026-07-28

适用对象：

- AI 管理页运营人员
- AI 管理页测试人员
- 需要人工复核清洗结果的业务人员

## 1. 入口与范围

当前测试页路径：

```text
/ai-management-test
```

当前正式文档清洗能力只服务 `general` 知识库。

当前页面支持：

- 查看可用清洗策略
- 上传多个文件创建批次
- 查看批次、文件、条目状态
- 重试失败文件
- 重试失败条目
- 对待复核条目执行人工复核

## 2. 上传前先确认

1. 选择正确知识库：当前一般使用 `general`
2. 选择正确策略
3. 确认文件格式受支持
4. 公共 Metadata 只填写已允许字段

当前正式策略：

- 微信公众号认知分享
- 个人商业咨询案例总结
- 知识星球帖子
- 小报童帖子
- 资料钩子
- 书籍

## 3. 页面操作顺序

### 3.1 查询策略

先点“获取策略列表”，确认当前知识库下有哪些策略可用。

### 3.2 上传文件

上传时填写：

- `knowledge_base_code`
- `strategy_code`
- `upload_mode`
- `common_metadata`
- 文件列表

约束：

- `.txt` 按文本读取
- 其它支持格式按 Markdown 清洗链路处理
- 单批次和单文件大小受服务端限制
- 不支持的扩展名会直接失败

### 3.3 看批次结果

批次需要重点看这些字段：

- `status`
- `progress`
- `all_succeeded`
- `all_processed_without_error`
- `file_counts`
- `item_counts`

判断原则：

- `status=completed` 代表批次终态已稳定
- `all_succeeded=true` 代表所有文件都成功
- `all_processed_without_error=true` 代表没有失败文件、没有待复核文件、没有 mixed 文件

### 3.4 看文件结果

每个文件重点看：

- `status`
- `outcome`
- `stage`
- `error_code`
- `error_message`
- `source_deleted_at`

常见情况：

- `succeeded`：文件下全部条目成功
- `failed`：文件级失败
- `review_required`：文件下全部条目都待人工复核
- `mixed`：同一文件下既有成功也有失败或待复核

### 3.5 看条目结果

进入文件条目列表后，重点看：

- `status`
- `stage`
- `metadata`
- `chunking`
- `dify_document_id`
- `remote_parent_count`
- `remote_child_count`

条目详情页还要看：

- `cleaned_markdown`
- `audit`
- `warnings`

## 4. 什么时候要人工复核

出现以下情况时不要直接当成功：

- `status=review_required`
- `retryable=false`
- `error_code=TOPIC_REVIEW_REQUIRED`
- `warnings` 提示存在主题不稳定或内容冲突
- 清洗正文明显缺失关键信息
- Metadata 中主题、来源标题不正确

## 5. 如何复核

复核接口支持三种动作：

- `approve`
- `replace_and_approve`
- `exclude`

建议使用方式：

- 内容基本正确，只需要补少量 Metadata：`approve`
- Markdown 正文需要人工修订后再入库：`replace_and_approve`
- 这条内容不该入库：`exclude`

复核时必须带：

- `expected_revision`
- `reason`

如果是 `replace_and_approve`，还必须上传新的 Markdown 文件。

## 6. 如何重试

### 6.1 文件重试

适合：

- 文件级失败
- 文件下存在失败条目

效果：

- 重新提交整个失败文件，或重新触发该文件下失败条目

不适合：

- 纯待复核文件

说明：

- 如果文件下全部条目都是 `review_required`，文件重试会返回 `409`；
- 这不是系统故障，而是强制要求先做人工复核。

### 6.2 条目重试

适合：

- 单条目失败

效果：

- 只重放这一条，不影响同文件下其它已成功条目

不适合：

- `status=review_required` 的条目

说明：

- 待复核条目必须先走复核接口；
- 选择 `approve` 或 `replace_and_approve` 后，系统会自动重新提交条目，不需要再额外点一次“重试”。

## 7. 成功与失败的判定口径

不要把“接口返回 200”当成成功。

条目真正成功，至少要满足：

1. Dify 文档创建成功
2. 索引完成
3. 父子块结构校验通过
4. Metadata 写入并回读成功

文件真正成功时：

- 文件状态为 `succeeded`
- 成功源文件已经删除

## 8. 需要特别注意的地方

- 成功文件源文件会删除，失败文件会暂存一段时间。
- 同名同内容文档可能被判定为重复跳过，不会重复索引。
- 书籍类大文件在 Markdown 成品超过 `10MB` 时会自动拆分。
- `exclude` 不是“失败”，它会把条目标记为排除，并同步刷新文件与批次统计。
- 页面根路径不是 `/`，测试页路径是 `/ai-management-test`。
- 验收或测试产生的临时知识库文档，结束后要删除，避免污染测试知识库。
- 如需保留 Dify 文档、只把测试页的清洗批次和上传状态恢复为空，使用 [jx 文档清洗本地状态归零操作说明](jx文档清洗本地状态归零操作说明.md) 中的受控脚本；不要直接删表、清空 Redis DB 或删除整个上传卷。
