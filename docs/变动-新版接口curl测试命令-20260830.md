# 新版接口 curl 联通测试命令

> 用途：在 jx 服务器或能访问 AI 管理服务私网地址的 Linux 主机上，验证新版朋友圈顾问和日常写作接口是否联通。
> 仅使用合成用户和短文本；不要把 Token、真实用户信息或正式业务内容写入命令历史、报告或聊天。

1. ## 测试前准备

在服务器终端执行。默认 jx API 私网地址为 `172.30.157.197:8000`；如果调用方在 Docker 网络内，请把 `BASE_URL` 改成对应服务名地址。

```bash
set -u
export BASE_URL="${BASE_URL:-http://172.30.157.197:8000}"
export USER_ID="curl-contract-probe-20260830"

# 方式 A：交互输入令牌，不进入命令历史
read -rsp "X-Internal-Token: " INTERNAL_TOKEN
printf '\n'
export INTERNAL_TOKEN

# 不要执行 env、printenv、set 或 cat .env，避免输出其他密钥。
command -v curl >/dev/null || { echo "curl is required" >&2; exit 1; }
command -v jq >/dev/null || { echo "jq is required for automatic ID extraction" >&2; exit 1; }

export COMMON_HEADERS=(
  -H "X-Internal-Token: ${INTERNAL_TOKEN}"
  -H "X-User-Id: ${USER_ID}"
)
```

如果服务器上的 shell 不支持数组，改用每条 curl 命令中单独写两个 `-H`，不要把令牌替换成文档中的明文。

1. ## 服务健康检查

在 jx 宿主机上，API 可能没有监听 `127.0.0.1:8000`，应使用上面的私网 `BASE_URL`，或在 API 容器内执行。

```bash
curl --fail-with-body --silent --show-error \
  "${BASE_URL}/health/ready"
```

预期：HTTP `200`，响应中的 `status` 为 `ready`，database、redis、dify 均为 `true`。

1. ## 朋友圈顾问接口

### 3.1 查询 current

```bash
curl --silent --show-error --include \
  "${COMMON_HEADERS[@]}" \
  "${BASE_URL}/internal/v1/tools/moments/conversations/current"
```

预期：HTTP `200`。如果 `conversation_id` 为 `null`，表示当前没有会话，不是接口故障。

### 3.2 创建销售型会话

```bash
MOMENTS_CREATE_RESPONSE="$({
  curl --fail-with-body --silent --show-error \
    "${COMMON_HEADERS[@]}" \
    -H "Content-Type: application/json" \
    -X POST \
    "${BASE_URL}/internal/v1/tools/moments/conversations" \
    --data '{"type":"sales"}'
} )"
printf '%s\n' "${MOMENTS_CREATE_RESPONSE}"
export MOMENTS_ID="$(printf '%s' "${MOMENTS_CREATE_RESPONSE}" | jq -r '.conversation_id')"
test -n "${MOMENTS_ID}" && test "${MOMENTS_ID}" != null || { echo "moments conversation_id missing" >&2; exit 1; }
```

预期：HTTP `200`，返回 `kind=moments`、`type=sales` 和本地 `conversation_id`。

### 3.3 朋友圈 run（SSE）

```bash
curl --silent --show-error --no-buffer --include \
  "${COMMON_HEADERS[@]}" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -X POST \
  "${BASE_URL}/internal/v1/tools/moments/run" \
  --data "$(jq -n \
    --arg id "${MOMENTS_ID}" \
    '{conversation_id:$id,inputs:{request:"请写一条新品咖啡上新的朋友圈，突出低糖和便携。",source_material:"使用合成测试素材，不代表正式活动。",audience:"老客户",tone:"自然",constraints:"保持简洁"}}')"
```

预期：先建立 HTTP `200` SSE 响应，并能看到 `request_started`、`status`、`answer_delta`、`message_end` 或合法的 `error` 事件。`conversation_id` 必须在 JSON 顶层。

### 3.4 重置朋友圈会话

```bash
curl --fail-with-body --silent --show-error --include \
  "${COMMON_HEADERS[@]}" \
  -H "Content-Type: application/json" \
  -X POST \
  "${BASE_URL}/internal/v1/tools/moments/conversations/${MOMENTS_ID}/reset" \
  --data '{}'
```

预期：HTTP `200`，响应中的 `conversation_id`、`type`、`output_format` 和 `guide` 均为空；客户端应清除本地旧 ID，再重新选择类型并 create。

1. ## 错误契约探针

以下探针预期是错误状态，不要使用 `--fail`，否则 curl 会直接中止而看不到状态码。

### 5.1 旧的无 ID reset 路径必须是 404

```bash
curl --silent --show-error --output /tmp/moments-old-reset.body \
  --write-out 'HTTP %{http_code}\n' \
  "${COMMON_HEADERS[@]}" \
  -H "Content-Type: application/json" \
  -X POST \
  "${BASE_URL}/internal/v1/tools/moments/conversations/reset" \
  --data '{}'
```

预期：

```text
HTTP 404
```

### 5.2 `inputs.type` 必须是 422

```bash
curl --silent --show-error --output /tmp/moments-nested-type.body \
  --write-out 'HTTP %{http_code}\n' \
  "${COMMON_HEADERS[@]}" \
  -H "Content-Type: application/json" \
  -X POST \
  "${BASE_URL}/internal/v1/tools/moments/run" \
  --data "$(jq -n --arg id "${MOMENTS_ID}" '{conversation_id:$id,inputs:{request:"字段校验探针",type:"sales"}}')"
```

预期：

```text
HTTP 422
```

### 5.3 顶层未知字段必须是 422

```bash
curl --silent --show-error --output /tmp/moments-unknown-field.body \
  --write-out 'HTTP %{http_code}\n' \
  "${COMMON_HEADERS[@]}" \
  -H "Content-Type: application/json" \
  -X POST \
  "${BASE_URL}/internal/v1/tools/moments/run" \
  --data "$(jq -n --arg id "${MOMENTS_ID}" '{conversation_id:$id,inputs:{request:"字段校验探针"},unexpected_field:true}')"
```

预期：

```text
HTTP 422
```

### 5.4 缺少顶层 `conversation_id` 必须是 422

```bash
curl --silent --show-error --output /tmp/moments-missing-id.body \
  --write-out 'HTTP %{http_code}\n' \
  "${COMMON_HEADERS[@]}" \
  -H "Content-Type: application/json" \
  -X POST \
  "${BASE_URL}/internal/v1/tools/moments/run" \
  --data '{"inputs":{"request":"字段校验探针"}}'
```

预期：

```text
HTTP 422
```

1. ## 结果判定

| 结果 | 判断 |
| --- | --- |
| 健康检查不是 HTTP 200 | 服务地址、容器或网络不通，先不要判断业务接口 |
| current/create 返回 401 | `X-Internal-Token` 或请求头配置错误 |
| create 返回 409 | 当前会话已存在且选择了不同类型/格式，先 reset |
| run 返回 422 | 检查 `conversation_id` 是否在顶层，并删除 inputs 中的控制字段 |
| run 返回 404 | 会话 ID 不存在、已 reset 或不属于当前用户 |
| SSE 连接 200 但无事件 | 检查反向代理缓冲、超时和 Dify 可达性 |
| 旧 reset 路径返回 200 | 服务器运行的不是当前发布版本，需要核对镜像/release |

测试结束后可删除临时错误响应体：

```bash
rm -f -- /tmp/moments-old-reset.body /tmp/moments-nested-type.body \
  /tmp/moments-unknown-field.body /tmp/moments-missing-id.body
unset INTERNAL_TOKEN COMMON_HEADERS MOMENTS_ID WRITING_ID USER_ID BASE_URL
```

不要清空 Redis、数据库或 Dify Dataset；本测试只使用合成会话和精确 reset。
