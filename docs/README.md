# jx-now 文档索引

> 状态：当前有效  
> 用途：按任务定位权威文档、源码和测试，避免每次全局扫描  
> 最后核对：2026-08-03

## 1. 使用方式

1. 先读根 `AGENTS.md`。
2. 先在[功能与接口索引](功能与接口索引.md)按功能名、HTTP 路径或工程入口定位；再用本页“功能阅读与更新矩阵”确认权威资料。
3. 只读对应权威文档、命中的源码和测试；需要线上事实时再读当前状态。
4. 日期化记录用于证据和复盘，不自动覆盖当前需求。
5. 发现冲突时按下述权威顺序裁决，并同步修正索引或 ADR。

## 2. 权威顺序

1. 用户当前明确确认的规则，以及最新 ADR。
2. [V2 决策记录](V2决策记录.md)、[V2 需求规格](V2需求规格说明.md)、[V2 产品流程与边界](V2产品流程与边界.md)、[V2 服务开发与数据设计](V2服务开发与数据设计.md)。
3. 当前专项接口、清洗、测试与部署规范。
4. [当前状态与后续测试交接](../AI管理服务当前状态与后续测试交接.md)的最新事实区。
5. 日期化验收、发布和排坑证据。
6. 标记为历史的旧计划、交接和快照。

### 3.1 需求来源与追踪

以下文件是原始业务来源材料，用于追溯意图和发现候选需求；它们不直接构成需求基线，也不自动覆盖当前运行事实。先读命中功能域的 V2 权威文档，只有需要核对原始意图、容量假设或场景增量时才读取来源材料。

| 来源材料 | 权威级别 | 命中场景才读取 | 对照或转化目标 | 变更处理 |
|---|---|---|---|---|
| [背景介绍.txt](../背景介绍.txt) | 项目背景、容量和原始约束来源；不是需求基线或当前运行事实 | 产品范围、容量/性能、上传约束、清洗规模、部署资源 | [V2需求规格说明.md](V2需求规格说明.md)、[V2服务开发与数据设计.md](V2服务开发与数据设计.md)、[清洗策略接入与编写规范.md](../清洗策略接入与编写规范.md)；动态版本和资源另与当前状态、部署手册核验 | 先澄清单位、时效和约束性质；只把确认后的语义增量同步到权威资料与测试 |

修改来源材料时不得把整篇内容机械复制到 `AGENTS.md` 或多份规范。先做语义差异核对，再更新真正受影响的权威文档、接口和测试；只有文件路径、用途或权威状态变化时才调整本表。

| `demo/` | 静态产品原型 | 参考，不代表真实接口 |
| `文件清洗样本/` | 真实或敏感验收输入 | 不提交；报告不记录正文和原始敏感名 |
| `部署问题/` | 外部部署资料/现场输入 | 按内容核验，不自动视为权威规范 |
| `var/reports/` | 原始测试和发布证据 | 不提交；只发布脱敏摘要 |

根目录的 Word、图片和业务材料按资料输入处理；只有经确认并转化为 ADR、需求或专项规范的内容才具有实现约束力。

## 10. 更新触发器

- 新增、删除、重命名文档或改变权威状态：更新本页。
- 修改业务来源材料：核对“需求来源与追踪”，比较语义增量；仅将用户确认后的变化同步到对应 V2/专项规范和测试。
- 改目录、入口、职责、依赖或主要数据流：更新“项目目录结构”。
- 改长期产品/架构决定：新增或替代 ADR。
- 改公开行为：更新对应接口/清洗/产品规范和测试。
- 改 HTTP 接口、CLI、Worker、Compose、Dify 资产或发布/RAG 脚本：运行 `python scripts/generate_project_index.py --write`，再运行 `--check`。
- 完成远端发布：最后更新当前状态、日期化验收和排坑记录。
- 只产生一次性运行证据：写 `var/reports/`，不要塞入 `AGENTS.md`。
