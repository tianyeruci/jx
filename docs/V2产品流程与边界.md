# AI 管理服务 V2 产品流程与边界

> 本文描述目标产品行为，不代表当前代码已全部实现。P1、P2、H 为历史资料，V2 文档为唯一基线。

## 1. 产品入口

用户首页只展示三个入口：

1. **商业顾问**：有历史、多会话、课程推荐和学习路线。
2. **朋友圈**：单次生成，不保存历史。
3. **写作**：单次生成，不保存历史。

课程不是第四个入口。课程卡片只在商业顾问给出合规推荐时出现。

## 2. 商业顾问主流程

```text
选择/新建本地会话
  → 输入问题
  → 服务取得同会话分布式锁
  → 持久化用户消息
  → 按当前轮明确表达、最近未摘要历史明确确认、摘要确认、路线进度、用户画像的顺序读取上下文
  → 创建/复用当日 Dify 会话段并流式调用
  → 转发 SSE 文本/状态
  → 服务端校验推荐候选并生成课程卡片
  → 持久化终态与指标
  → 可靠触发摘要任务
  → 释放锁
```

异常规则：

- 同会话已有生成任务：返回 409；不同会话可并行。
- 用户停止：请求 Dify 停止并把本地消息置为确定终态。
- 客户端断开：服务仍完成停止/持久化/任务入队清理，不能依赖客户端继续读流。
- Dify 超时或失败：返回稳定错误事件，保留已产生的诊断信息，不伪装成功。
- 摘要失败：保留原消息、记录事件并重试，不推进清理游标。

## 3. 跨日、摘要和保留

- 本地会话跨日保持同一 ID；每个自然日使用新的 Dify 会话段。
- Dify Memory 关闭；上下文由本服务每轮动态构建。
- 摘要覆盖到 `summary_through_message_id`；游标后的有效消息最多取 50 条，再按字符预算裁剪。
- 7 天清理只处理已由摘要覆盖的原始消息和可安全删除的旧 Dify 段。
- 无法确认摘要完整性时，状态标记为 gap 并暂停删除。

## 4. 课程推荐、路线和点击

```text
明确课程、课程集或最新课程查询
  → 服务校验候选课程
  → 生成独立课程卡片和短期签名跳转链接

路线型学习诉求
  → 缺少会实质改变路线的关键信息时澄清必要信息
  → 多个可信官方路线 → clarification，等待用户选择
  → 无官方路线证据 → 说明未匹配并转为独立课程路径
  → 唯一官方路线 → awaiting_route_confirmation
  → 用户明确确认路线 → awaiting_stage_confirmation
  → 用户明确确认当前阶段 → active
  → 仅按该路线的当前阶段、下一阶段顺序生成最多 5 张课程卡片
  → 用户明确完成或跳过当前阶段后才推进

课程卡片点击
  → 用户点击 /r/{token}
  → 验签并确认课程仍可用
  → 当日 PV +1、匿名 UV 去重
  → 302 跳转正式课程地址
```

- PV 是课程链接被点击的总次数，也是后台主指标；同一用户多次点击会多次计数。
- UV 是匿名点击人数的辅助指标，同一匿名用户同课程同日只计一次。
- 无效、过期或指向停用课程的 Token 不计数、不跳转。
- 点击不等同学习完成，不推进路线。
- 路线或阶段待确认时，`learning_route` 可展示经审核的完整阶段和课程名称以便用户判断，但不能生成 `course_cards`，也不能把这些名称写成已推荐课程。
- 多条官方路线都可能匹配时，先澄清让用户选择；不得降级为独立课程推荐。确实没有官方路线证据时，可明确说明未匹配后转为独立课程路径。用户可以并存多条路线进度，明确选择新路线不自动取消旧路线；拒绝、换一条或含糊答复不写持久拒绝状态。
- 运营人员可通过 CLI 校验/发布课程和路线，也可在管理员清洗页选择 `course_information` / `learning_route` 策略发布；两条入口必须复用同一目录校验、Dify 验证、数据库事务和补偿规则。当前仍没有通用课程 CRUD 后台。

## 5. 清洗流程

```text
选择策略和目标测试知识库
  → 上传文件并校验数量/大小/类型/文件头/路径
  → 创建批次与逐文件任务
  → 按支持矩阵统一转换/规范化为 Markdown
  → 清洗 Markdown 表格（不可靠表格线性化并内部审计）
  → 执行所选策略、模型/复核和策略级分片
  → 最终无 Markdown/HTML 表格门禁，合并系统 Metadata 与 content_format=markdown
  → Dify create-by-text 发送清洗正文并等待索引
  → 校验非零分块
  → 成功，或删除已创建远端文档进行补偿
```

批次允许部分成功。自动重试最多一次；人工重试只针对可重试失败。补偿失败进入外部删除任务并在后台显示。

## 6. 内部运维流程

- Streamlit 通过服务 API 查看点击汇总、清洗状态、必要操作和错误事件。
- 管理请求使用独立 Admin Token；页面固定绑定服务器 `127.0.0.1`。临时测试通过 Dify 已有 Nginx 的 `/ai-management-test/` 路径访问，复用既有 80/443，不新增端口或云安全组规则；测试结束移除该路由。
- 完整容器调试日志从 stdout/日志平台读取；事件后台只保存运维必要摘要。
- 运营可按 request ID、task ID、资源 ID 从页面定位问题，不显示用户完整对话或密钥。

## 7. 静态 Demo 与真实系统边界

- 静态 Demo 位于独立 `demo/`，只用于确认页面结构、术语、空态、错误态和交互路径。
- Demo 使用合成课程和模拟状态，不调用服务器、Dify 或正式链接。
- Streamlit 是集成测试和内部运维工具，不是用户产品，也不替代小程序 E2E。
- Demo 评审若改变入口、发布方式或会话架构，必须先更新 V2 决策和需求再开发。

## 8. 产品范围外

完整课程后台、逐次点击审计、点击驱动学习进度、动态策略平台、朋友圈/写作历史、公开运维页面以及服务器内直接改代码，均不属于 V2 首版。
