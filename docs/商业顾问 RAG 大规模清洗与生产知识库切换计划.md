# 商业顾问 RAG 大规模清洗与生产知识库切换计划

## 摘要

所有已识别的高影响需求均已确认。目标不是机械去广告，而是依据《AI商业顾问RAG全链路执行计划》，为商业顾问问答保留直接商业知识、可迁移决策认知及其必要证据、条件和限制。

生产清洗模型不再使用 Dify Workflow。程序直接调用百炼：

- 小任务及匿名化咨询走实时 `qwen-plus`。
- 大批量公众号、知识星球、小报童走 Batch API。
- Dify 只负责知识库存储、索引和商业顾问问答。
- 多帖文件改为“帖子本地独立＋Dify 分片原子”，替换此前不适合十万级数据的整文件原子规则。

百炼 Batch API 支持每文件最多 50,000 个请求、500MB、24 小时完成窗口，价格为实时调用的 50%。[官方批量推理说明](https://help.aliyun.com/zh/model-studio/batch-inference)

## 核心实现

### 确定性解析与商业语义

- 所有来源先完成格式解析、文章/帖子边界识别、内容指纹、精确去重、平台噪声清理和来源块编号。
- 原文件名只用于后台管理、溯源和咨询隐私候选，不进入 Prompt、相关性判断、正文标题补全、分块上下文或业务身份。
- 相同内容、不同文件名只处理一次；相同文件名、不同内容不自动替换。
- 四类模型策略逐候选产生独立判断：
  - `personal_business_consultation`
  - `wechat_public_account_cognition`
  - `zsxq_post`
  - `xiaobot_post`
- `book`、`lead_magnet` 不调用模型，信任上传范围，只执行确定性结构清洗。

### 模型调用双通道

- 咨询始终先匿名化，再使用实时 API。
- 其他三类满足以下任一条件时使用 Batch API：
  - 候选数超过 100；
  - 预计输入超过 200,000 tokens。
- 每个帖子仍对应一个独立模型请求；不把多帖塞进同一上下文，避免串扰。
- Batch JSONL 按同策略、同模型、同 Prompt 版本拆分，每个文件最多 40,000 条或 400MB，给官方上限留安全余量。
- `custom_id` 使用内部条目 ID、内容指纹和 Prompt 版本生成，不包含文件名或正文。
- 使用独立、最小权限的百炼 API Key，不读取或复用 Dify 内部保存的模型凭证。
- 模型参数固定为：
  - `model=qwen-plus`
  - `temperature=0`
  - 非思考模式
  - `response_format={"type":"json_object"}`
  - 不设置可能截断 JSON 的 `max_tokens`
- Prompt、JSON 契约和版本全部保存在仓库，由程序统一调用和校验。[千问结构化输出规范](https://help.aliyun.com/zh/model-studio/qwen-structured-output)

### Prompt 与证据契约

- 公众号、知识星球、小报童只返回：
  - `disposition`
  - `business_relevance`
  - `reason_code`
  - `keep_block_ids`
  - `drop_block_ids`
  - `topic`
  - `time_sensitive`
  - `confidence`
- 程序按来源块原顺序组装正文，模型不得自由改写。
- 咨询返回六类可选章节，每个输出段必须绑定来源块 ID，并标明客户陈述、顾问判断、决定、计划或实际结果。
- 校验数字、日期、否定、人物归属、事实状态和来源块范围；非法 JSON、无证据判断或内容变义重试一次，仍失败则转人工复核。
- 单候选超过 12k tokens 不自动截断或摘要，转人工复核。

### 商业价值与广告边界

- 纯红包、招募、节日问候、行政通知、闲聊或只要求添加联系方式的内容整条排除。
- 商业正文附带微信、二维码、报名或引流尾部时，只删除联系方式和推广尾部。
- 推广本身是营销策略、案例复盘、成交方法或可迁移决策证据时保留。
- 推广与论证无法无损分离时转复核。
- 关键词只负责定位候选，不直接决定删除。
- 知识星球现有 8 个样本纳入本地回归；明确红包样本为强制排除金标，未标注样本只作诊断。

### PDF、表格和目录

- `table_review` 分级：
  - 仅列对齐不可靠、线性文本完整可读且无 OCR/隐私风险：记录告警并继续。
  - 单元格缺失、顺序错误、数值归属不明、OCR 或隐私不确定：转人工复核。
- `book` 和 `lead_magnet` 使用相同的可选目录流程：
  - 综合目录标记、密集页码条目、页码单调性和正文标题对应关系识别目录。
  - 可信目录仅用于恢复层级，目录页和目录列表不入库。
  - 没有目录时按正文标题和段落正常分块。
  - 疑似目录但无法与正文可靠对应时转复核。
- 目录标题只有在正文中找到证据时才能作为父块层级。
- 资料钩子的 15 份 PDF、14 份唯一内容覆盖显式目录、隐式目录、无目录、异常 PDF 和跨文件精确重复。

### 公共清理

所有策略清洗结果在发布前统一：

- 保留 Markdown 结构地折叠连续空格、制表符和多余空行。
- Markdown 链接保留锚文本，删除目标 URL。
- 删除裸 URL、邮箱、手机号、微信号、QQ、二维码和纯联系操作句。
- 咨询执行匿名化及正文、标题、Metadata 残留隐私扫描。
- Dify 同时开启 `remove_extra_spaces` 和 `remove_urls_emails`；`raw` 原样上传模式不变。
- 远端验收必须证明这两个选项没有破坏父子分隔符、表格和 Markdown 层级，否则停止发布并修正格式契约。

## 大规模任务、分片与状态

### 模型任务

- 新增模型任务记录，保存调用模式、模型、Prompt 版本、候选数、预计 tokens、预计费用、百炼 Batch ID、文件 ID、结果计数及清理状态。
- 上传完成确定性解析后，大任务进入 `awaiting_model_approval`。
- 管理页展示候选数、预计输入/输出 tokens、费用区间、Batch 文件数和预计 Dify 分片数。
- 管理员确认费用快照后才上传 JSONL；候选集或价格版本变化会使旧确认失效。
- 百炼任务按 60 秒间隔轮询，不占用长时间 Celery 执行槽。
- 行级失败或契约错误汇总重试：
  - 不足 100 条走实时 API；
  - 100 条及以上生成一个补偿 Batch；
  - 每条最多重试一次。
- Batch 输入、输出和错误文件验证完成后按精确 file ID 删除；删除失败进入外部清理任务。官方说明上传文件默认持续保存，必须主动删除。[百炼文件接口](https://help.aliyun.com/zh/model-studio/openai-file-interface)

### Dify 发布分片

- 每个帖子在本地保持独立状态、内容指纹、模型结果和审计证据。
- 同一来源文件、同一策略内，通过的帖子按以下上限组成 Dify 分片：
  - 最多 200 帖；
  - 或清洗后 UTF-8 正文达到 1MB；
  - 任一条件先达到即结束当前分片。
- 每帖是一个独立父块，不能跨帖生成子块。
- Dify 分片是远端发布和补偿的原子单元；某分片失败只回滚该分片，不影响其他已验证分片。
- 待复核帖子不进入分片，也不阻止同文件其他帖子发布。
- 删除或更新某帖时，重建并精确替换其所在分片。
- 咨询、书籍、资料钩子及单文档 PDF 仍保持源文件全有或全无。
- 原文件只有在所有帖子均已成功、明确排除且无待复核/失败项后才删除；否则按保留期保存。

### 资源隔离

- 增加独立队列：
  - `ai_model_realtime`：实时模型任务，初始并发 4，按 RPM/TPM 双令牌桶限速。
  - `ai_model_batch`：Batch 提交、轮询和结果处理，初始并发 1。
  - `ai_publication`：Dify 分片创建和索引，初始并发 1。
- Batch 模型推理不占用 Dify Worker。
- Dify 发布默认只在 `00:00–06:00 Asia/Shanghai` 执行；窗口外保持排队。
- 每个分片必须验证创建、索引终态、父子块数量、非空 token 和 Metadata 回读后才提交本地成功状态。
- 所有任务使用内容指纹和唯一约束保证重启、重复回调和重复下载不产生重复文档。

## API、数据和配置

- 现有上传、状态、重试和人工复核接口保持兼容。
- 新增：
  - 大模型费用审批接口；
  - 模型任务取消接口；
  - 模型任务及 Dify 分片状态查询；
  - 分片级重试和精确替换能力。
- 状态新增：
  - `awaiting_model_approval`
  - `model_batch_uploading`
  - `model_batch_running`
  - `model_validating`
  - `shard_pending`
  - `shard_indexing`
  - `partially_completed`
- 新增模型任务表、Dify 发布分片表及条目到分片的映射；历史 `CleaningDocument.dify_document_id` 保留兼容，新流程优先读取分片映射。
- 新增配置：
  - 专用百炼 API Key 和区域 Endpoint；
  - 模型、实时/Batch 阈值、并发和限速；
  - Prompt 版本；
  - 当前官方价格快照及生效日期；
  - Dify 发布时间窗和分片上限。
- 价格配置缺失或过期时禁止批准大任务，不使用猜测价格产生付费调用。

## 生产切换

- 发布前备份并验证恢复：AI 数据库、上传卷、Redis、环境配置、旧镜像、Dify 数据集绑定和 Chatflow 发布版本。
- 使用同一不可变构建发布 API、三个专用 Worker、Scheduler 和测试页。
- 先以脱敏合成数据完成实时 API、Batch API、文件删除、分片索引和故障恢复验收。
- 将服务知识库绑定切换到新 `general`、`course`。
- 重新绑定并发布商业顾问 Chatflow 的知识检索节点。
- 从权威数据库重新发布正式课程和路线到新 `course`。
- 旧测试知识库保持不变，不迁移其普通资料。
- 新 `general` 在验收数据精确清理后为空，等待正式资料重新上传。
- 测试数据只按精确 Batch/file/document ID 清理，不使用文件名或正则猜测归属。
- 失败时恢复旧服务构建、知识库 ID 和 Chatflow 已发布版本，不删除新旧知识库。

## 测试与验收

- 功能回归：
  - 同正文不同文件名得到相同候选、Prompt、模型输入和内容身份。
  - 红包、纯联系方式、混合推广、营销复盘和范围外内容符合商业价值边界。
  - 咨询六段式结构保持数字、否定、人物和状态。
  - 多 PDF 不因非阻断表格告警丢失。
  - 有目录、隐式目录、无目录和疑似目录均按确认规则处理。
  - 入库正文无目录列表、URL、邮箱和联系方式。
- 批量可靠性：
  - 用合成 100,000 条候选验证流式生成 JSONL，进程内存不超过 512MB。
  - 100,000 条候选拆为 3 个以内 Batch 文件，并通过 `custom_id` 完整守恒。
  - 验证 Batch 乱序结果、重复行、缺失行、部分错误、任务过期、取消及服务重启。
  - 数量守恒：输入数等于重复、排除、复核、失败和入库条目总和；每个入库条目只属于一个分片。
  - 100,000 条、每分片 200 条时远端文档数不超过约 500 个，实际还受 1MB 上限约束。
- 并发与隔离：
  - 模型 Batch 运行期间商业顾问问答不经过清洗队列。
  - 发布时间窗外不启动 Dify 建库。
  - 429、TPM、突发限流采用平滑发送和指数退避，不切换模型或降低证据要求。[百炼限流最佳实践](https://help.aliyun.com/zh/model-studio/rate-limiting-best-practices)
- 数据与费用：
  - 未审批的大任务不会产生模型调用。
  - 实际 tokens、费用和预估差异进入验收报告。
  - 百炼输入、输出和错误文件均有精确删除证据。
  - 本地真实样本不进入远端验收报告，不输出正文或真实文件名。
- 文档同步：
  - 用 ADR 记录“程序直连百炼、双通道模型调用、帖子级处理、Dify 分片原子”。
  - 同步全链路计划、四类策略规范、清洗接入、接口索引、数据设计、Dify 指南、部署回滚和验收规范。
  - 只有经过验证的故障经验才写入长期排障文档。

## 已锁定假设

- 大批量模型任务允许最长 24 小时，并必须经过费用预览和管理员确认。
- 每个帖子保持独立模型判断，不使用多帖共用一次推理。
- 多帖来源允许部分帖子成功；远端原子边界改为 Dify 分片。
- `book`、`lead_magnet` 的商业主题范围由上传者负责。
- 咨询不使用 Batch 文件，只使用匿名化后的实时 API。
- 不使用 Dify Workflow 执行生产清洗，不迁移旧测试普通资料，不删除旧测试知识库，不执行 Git push。

## 2026-08-01 实施核验与剩余门禁

### 已验证

- R20c 已部署到 jx；程序直连百炼的实时/Batch 双通道、模型任务轮询、结构化契约校验、人工审核和 Dify 发布链路可运行。大批量清洗不依赖 Dify Workflow 编排：Dify 仅负责知识库存储、索引和在线商业顾问问答。
- 公众号真实页面批次处理 `128` 个候选，结果为 `106` 成功、`14` 排除、`8` 待复核；这证明“商业相关性过滤”生效，但不把所有广告样式内容机械删除。
- 课程路线合成工作簿完成 3 门课程、2 条路线的模型候选→审核表→批准发布；5 份文档均通过索引、父子块、Metadata、URL/邮箱扫描。
- 书籍和资料钩子目录采用可选识别：有目录时只用于父子层级，不入库；无目录按正文标题分块。PDF 表格仅有线性文本且可读时记录告警并继续，不能可靠对齐或存在隐私/数值归属风险时进入复核。
- 所有本轮测试批次、测试用户、任务结果键和残余测试 Dify 文档均按精确归属清理；正式课程、路线和正式 Dify 文档未被清理。

### 仍需完成后才可称为生产切换

- 20 并发、持续 10 分钟的真实流式压测已完成：400/400 成功、0 失败，首事件 P95 约 503ms、总耗时均值约 17.9s；这只覆盖在线问答入口，不替代清洗 Batch 压力测试。
- 隔离环境的故障/补偿/精确清理回归已完成 `20/20`；它覆盖代码级失败路径，不代表已在正式 Dataset、Redis、PostgreSQL 或 Worker 上做破坏性演练。
- 完成生产 Dataset 破坏性故障注入、Redis/PostgreSQL/Dify/Worker 故障恢复、小程序真实客户端端到端、40 条人工语义门禁和灰度发布。
- 当前用户提供的课程工作簿不满足规格，不能用合成工作簿结果替代正式 137 行目录核验；正式目录导入必须重新提供结构完整、可审计的源表。
- 临时公网 HTTP `/ai-service/` 仅用于联调，Token 明文传输风险未解除；正式使用前切换 HTTPS 或恢复私网访问。
