## 4. RAG 检索评测

导入通用资料和课程资料后：

```powershell
ai-rag-eval test_data/rag/golden_questions.jsonl --top-k 5 --output var/reports/rag.json
```

工具对有标准相关文档的用例计算 Recall@5、MRR 和 HitRate@5；无答案、停用过滤、进度不推进和路线不篡改用例列为完整 Chatflow 行为检查，不能用检索命中率替代。

验收门槛：

- 关键问题 Hit@5 ≥ 90%。
- 全量 Recall@5 ≥ 80%。
- 引用完整率 ≥ 90%。
- 无依据回答率 ≤ 5%。
- 错误课程 ID、错误正式链接、虚构路线均为0。

至少人工检查10条完整回答。

### 4.1 小项目推荐的三层评测

不要只看一个“准确率”。商业顾问链路拆成三层即可：

1. 知识库直检：`ai-rag-eval` 计算 Recall@5、Hit@5、MRR，定位分块、Embedding、Top-K 和资料问题。
2. 全链路规则评测：调用 AI 管理服务真实 SSE，校验课程 ID、路线 ID、停用过滤、拒答、首 Token 和总耗时。
3. 少量人工抽检：每次发布人工看 5～10 条回答的事实依据、完整性和表达，不引入 LLM Judge 作为首版门禁。

全链路命令：

```powershell
python scripts/evaluate_business_e2e.py `
  test_data/rag/business_e2e_cases.jsonl `
  --base-url http://127.0.0.1:8000 `
  --token "<INTERNAL_API_TOKEN>" `
  --output var/reports/business-e2e.json
```

脚本为每条用例使用独立测试用户，结束后删除测试会话。报告包含逐例断言、通过率、首 Token P50/P95 和总耗时 P50/P95。

首版不建议直接引入 Ragas、DeepEval 或 Promptfoo。它们适合需要 LLM Judge、多个模型/Prompt 对比或 CI 平台化之后再接入；当前以确定性结构化断言为主，更便宜、稳定、容易解释。

## 6. 并发与故障

最低执行：

- 20个不同会话并发流式请求，持续10分钟。
- 同一会话并发返回409。
- 客户端断开后 Dify 停止和本地状态正确。
- Dify 超时/限流/不可用。
- Redis、PostgreSQL 短暂不可用。
- Worker 重启、清洗任务自动重试一次。
- 200MB 流式上传。

`p95 < 200ms` 只统计服务开始响应 SSE 状态事件的自身开销，不包含模型生成时间。

20并发10分钟脚本：

```powershell
python scripts/stream_load_test.py `
  --token "<INTERNAL_API_TOKEN>" `
  --concurrency 20 `
  --duration-seconds 600
```
