# AI 管理服务 V2 服务开发与数据设计

> 状态：目标设计；实施结果需在代码完成后回填为 as-built。P1、P2、H 为历史资料，V2 为唯一基线。

## 1. 架构与职责

- FastAPI：HTTP/SSE、鉴权、Schema、健康检查。
- Service：会话、摘要、推荐、点击、课程发布、清洗和事件规则。
- PostgreSQL：业务事实、每日点击汇总、运维事件和补偿任务。
- Redis：Celery Broker、课程快照、分布式锁、点击实时计数与 UV 集合。
- Celery Worker/Beat：摘要、清洗、夜间汇总/清理和外部补偿。
- Dify：一个商业 Chatflow、三个无状态 Workflow（朋友圈、写作、摘要画像）和两个知识库。

## 2. 会话数据流与事务

聊天请求先校验用户和会话归属，再取得可续租分布式锁。事务 A 写入用户消息并提交；随后构建上下文并调用 Dify。流式期间只累计必要状态，终态在事务 B 中写入助手消息、推荐、耗时和 Dify 标识，并创建可靠摘要任务记录/入队标记。SSE `message_end` 只能在终态持久化和可靠入队完成后发送。

上下文查询以 `summary_through_message_id` 定位游标消息的 `(created_at, id)`，只查该位置之后 `status=completed` 的最近 50 条，再按 `CONTEXT_MAX_CHARS` 从新到旧裁剪并恢复时间顺序。新增复合索引：

```text
business_message(conversation_id, status, created_at, id)
```

摘要 Worker 按稳定顺序分批读取游标后消息，单批不超过 Workflow 输入限制。摘要、画像候选和新游标在同一事务内比较并更新；旧游标已推进时任务退出，不覆盖新结果。

## 3. 数据模型变更

保留现有会话、消息、段、画像、课程、路线、路线进度、点击日表、清洗和外部删除表，新增：

### `business_profile` 管理审计字段

`business_profile.user_hash` 继续作为会话隔离、画像和路线进度的内部关联键，不通过管理会话接口输出。新增可空、唯一并建立索引的 `user_id`，在每次商业聊天时使用 `X-User-Id` 创建或补齐，供双 Token 管理接口按真实用户 ID 查询和展示。

迁移不尝试从哈希反推原始 ID；历史记录在用户再次聊天前返回空 `user_id`。管理会话列表从最近一条助手消息读取推荐课程、历史专业见解、推荐理由、token 和耗时；详情在每条消息上提供相同结构，并在顶层重复最近助手消息的汇总。当前链路不重新生成 `expert_insight`。

### `system_event_log`

| 字段 | 类型/约束 | 用途 |
|---|---|---|
| `id` | UUID/字符串主键 | 事件 ID |
| `occurred_at` | 带时区时间，索引 | 发生时间 |
| `level` | `INFO/WARNING/ERROR/CRITICAL` | 等级 |
| `category` | 字符串，索引 | operation/error/task/security |
| `component` | 字符串，索引 | api/worker/scheduler/dify/redis/db |
| `event_code` | 字符串，索引 | 稳定机器码 |
| `status` | 字符串，索引 | started/succeeded/failed/retrying |
| `request_id` | 可空字符串，索引 | 请求关联 |
| `actor_hash` | 可空哈希 | 匿名操作者 |
| `resource_type/id` | 可空字符串，组合索引 | 会话、批次、课程或任务 |
| `summary` | 短文本 | 脱敏摘要 |
| `detail_json` | JSON | 白名单诊断字段 |
| `duration_ms` | 可空整数 | 耗时 |
| `build_version` | 字符串 | 版本 |

默认保留 30 天；清理任务写一条汇总事件。`detail_json` 使用字段白名单，禁止事后仅靠正则脱敏。

### 点击日表

继续使用 `course_click_daily(course_id, click_date, clicks, unique_users)`，唯一约束 `(course_id, click_date)`。不新增逐次点击表。

## 4. Redis 设计

建议 Key 均带环境前缀 `{APP_ENV}:ai:`：

| Key | 类型 | TTL/语义 |
|---|---|---|
| `conv-lock:{conversation_id}` | string/token | 生成期租约；续租仅限同 token，释放需原子比较删除 |
| `course-snapshot` | string/json | 课程发布后替换；失效可回源 DB 重建 |
| `clicks:{yyyy-mm-dd}:{course_id}` | counter | 每次有效跳转 `INCR`；至少保留 30 天 |
| `click-users:{yyyy-mm-dd}:{course_id}` | set/hash | 添加匿名用户哈希，至少保留 30 天 |
| `click-dirty-dates` | set | 记录所有待落库日期，成功 upsert 后移除 |

点击写入需以原子脚本/事务同时完成 PV、UV、dirty 标记和 TTL。夜间任务遍历所有 dirty 日期，不只处理“昨天”；读取 Redis 绝对值并用 PostgreSQL upsert 覆盖/取最大值，重复执行结果不翻倍。当天查询合并 DB 与 Redis，返回 `persisted_through` 和 `realtime=true/false`。

缓存异常可回源；会话锁异常时禁止状态写入并返回可重试服务错误。Redis AOF 开启，但 Redis 数据和 AOF 同时损坏造成的少计是已接受限制。

## 5. 课程发布一致性

`dry-run` 不产生外部写入。`publish` 顺序：解析和完整校验 → 生成目标清单 → 写入/更新 Dify 文档并确认索引与分块 → PostgreSQL 事务更新课程路线 → 更新 Redis 快照 → 对账新目录中消失、停用或未审核的旧 Dify 文档。

Dify 成功而 DB 失败时创建补偿删除任务；DB 成功而缓存失败时标记缓存待重建，API 回源 DB。旧文档停用/删除失败必须可查询、可重试，不能继续宣称发布完成。

## 6. 清洗状态与幂等

批次状态由文件状态聚合；文件阶段至少包含 upload/extract/transform/publish/index/compensate。任务幂等键使用文件 ID 和 attempt；重复任务先检查当前终态。每个远端文档 ID 在本地落库后再进入下一阶段。自动重试最多一次，人工重试创建新 attempt 并保留历史错误。

清洗准入使用单文件 200MB、单批 10 个/500MB、最多 5 个活动批次的配置门禁；PostgreSQL 创建批次时使用事务 advisory lock 串行化活动批次容量检查，避免并发请求突破上限。源文件以规范化名称和 SHA-256 做双重去重，任一命中都记录 `excluded/duplicate_noop`，只有精确源删除完成后才释放保护。删除源文件必须同步远端分片墓碑、`dedupe_released_at` 和批次终态聚合。

模型任务保存实际调用模式和独立价格快照。`BAILIAN_BATCH_ENABLED=false` 只影响新任务，已有任务不迁移；实时 Worker 受 RPM/TPM 和并发限制，Batch 轮询的瞬时数据库异常只重试本地轮询，不把供应商仍在运行的任务误判为失败。PDF/DOCX 转换 Markdown 为可选的服务器诊断产物，不进入业务表或 HTTP 响应；但无论诊断产物是否落盘，策略、模型和发布使用的正文都必须经过统一 Markdown 表格清洗和最终无表格门禁。

## 7. API 与错误约束

- 保持现有业务路由和 SSE 事件兼容；新增管理日志和增强点击查询接口。
- 管理接口统一 `/internal/v1/admin/*`，要求 `X-Admin-Token`。
- 错误响应含稳定 `code`、可读 `message` 和 `request_id`，不暴露堆栈或远端响应正文。
- 朋友圈/写作改为强类型字段；字段长度必须与 Dify DSL 同源或通过契约测试锁定。

## 8. 可观测性与版本

API 中间件产生/透传 request ID；异步任务继承 correlation ID。stdout 使用单行 JSON，关键字段为 timestamp、level、component、event_code、request_id/task_id、resource、duration_ms、build_version。镜像以发布号和源码提交哈希形成不可变标签，API/Worker/Scheduler 必须一致。
