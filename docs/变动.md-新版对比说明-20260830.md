# 新旧接口文档对比说明

> 对比对象：附件 `D:\收藏\桌面\变动.md` 与 [变动-新版接口文档-20260830.md](./变动-新版接口文档-20260830.md)。
> 目的：帮助小程序后端快速识别必须修改的调用方式。以下“新版”以当前 jx 已发布并通过联通验证的接口为准。

1. ## 总体结论

附件中的会话接口和 `/run` 请求体已过时，不能直接照抄。最重要的变化是：

1. `conversation_id` 从 `inputs` 移到请求体顶层；
2. 类型和写作格式从 `/run` 移到会话创建接口；
3. reset 从无 ID 路径改为带会话 ID 的路径；
4. reset 后返回空会话状态，不会自动创建新会话；
5. 非法字段现在明确返回 `422`；
6. 当前版本已在 jx 完成真实接口和测试页验收。

1. ## 逐项变化

| 对接项 | 附件 `变动.md` | 新版实际契约 | 小程序后端影响 |
| --- | --- | --- | --- |
| 朋友圈 create | `POST /moments/conversations`，请求体 `type`；方向正确 | 路径不变；需携带 `X-Internal-Token`、`X-User-Id`；返回本地会话 ID | 保存返回的本地 `conversation_id` |
| 写作 create | `POST /writing/conversations`，请求体含 `type/output_format`；方向正确 | 路径不变；`type` 和 `output_format` 在此选择 | 保存类型、格式和本地会话 ID |
| current | 路径基本一致 | 无会话时 `conversation_id=null`，不是故障 | 展示类型/格式选择，不自动运行 |
| 朋友圈 reset 路径 | `/moments/conversations/reset` | `/moments/conversations/{conversation_id}/reset` | 必须把当前本地 ID 放到 URL 路径 |
| 写作 reset 路径 | `/writing/conversations/reset` | `/writing/conversations/{conversation_id}/reset` | 必须把当前本地 ID 放到 URL 路径 |
| reset 响应 | 返回“新的本地工具会话 ID” | 返回 `conversation_id=null` 的空会话状态 | 清除旧 ID，重新选择后再 create |
| reset 后类型 | 文档要求重新展示选择，但示例仍返回新 ID | 不保留旧类型/格式 | 不要继续复用旧类型和格式 |
| moments/run 会话 ID | `inputs.conversation_id` | 顶层 `conversation_id` | 必须调整 JSON 层级 |
| writing/run 会话 ID | `inputs.conversation_id` | 顶层 `conversation_id` | 必须调整 JSON 层级 |
| moments/run 类型 | `inputs.type` | 不允许在 `inputs` 传 `type` | 类型以 create 的会话记录为准 |
| writing/run 类型 | `inputs.type` | 不允许在 `inputs` 传 `type` | 类型以 create 的会话记录为准 |
| writing/run 格式 | `inputs.output_format` | 不允许在 `inputs` 传 `output_format` | 格式以 create 的会话记录为准 |
| `inputs.format` | 附件未明确禁止 | 新版禁止 | 不要传该字段 |
| 未知字段 | 附件未定义 | 返回 `422`，`extra_forbidden` | 不要依赖服务端静默忽略 |
| 缺少会话 ID | 附件未明确 | `/run` 返回 `422`，不会自动创建 | 先 current/create |
| 会话不存在 | 附件未明确 | `/run` 返回 `404` | 清除本地 ID并重新建会话 |
| SSE | 附件列出事件名，方向正确 | 继续使用 `request_started/status/answer_delta/message_end/error` | 按事件边界解析 |
| 文本 reset | 附件未完整定义 | 仅 7 个精确短语触发 | 普通“开始写文章”不会误 reset |
| 商业顾问 | 附件未说明影响 | 本轮未修改 | 不需要改商业顾问接口 |
| 课程 Excel/学习路线 | 附件涉及或隐含旧范围 | 已退出当前范围 | 不纳入本轮对接和测试 |

1. ## 请求体变化示例

### 3.1 朋友圈 `/run`

**附件旧写法（不要继续使用）**

```json
{
  "inputs": {
    "conversation_id": "本地工具会话ID",
    "type": "sales",
    "request": "今天店里做会员日活动，帮我写一条朋友圈。"
  }
}
```

**新版写法**

```json
{
  "conversation_id": "本地工具会话ID",
  "inputs": {
    "request": "今天店里做会员日活动，帮我写一条朋友圈。",
    "source_material": "满199减50，活动只限今天，主推修护精华。"
  }
}
```

### 3.2 日常写作 `/run`

**附件旧写法（不要继续使用）**

```json
{
  "inputs": {
    "conversation_id": "本地工具会话ID",
    "type": "expand",
    "output_format": "wechat_public_account",
    "request": "帮我写一篇公众号文章。"
  }
}
```

**新版写法**

```json
{
  "conversation_id": "本地工具会话ID",
  "inputs": {
    "request": "帮我写一篇公众号文章。",
    "source_text": "我以前总想快速见效，后来坚持跑步半年，发现身体和情绪都稳定了很多。"
  }
}
```

新版请求之前必须先创建：

```json
{
  "type": "expand",
  "output_format": "wechat_public_account"
}
```

1. ## reset 调用变化

**附件旧写法（已失效）**

```http
POST /internal/v1/tools/moments/conversations/reset
```

**新版写法**

```http
POST /internal/v1/tools/moments/conversations/{conversation_id}/reset
```

写作接口同理。reset 成功后：

```json
{
  "message": "已开启新会话",
  "conversation_id": null,
  "kind": "moments",
  "type": null,
  "output_format": null,
  "guide": null
}
```

客户端必须清除本地旧 ID，回到选择界面，再调用 create。旧无 ID 路径在 jx 实测为 `404`。

1. ## 新版推荐对接流程

```text
进入朋友圈/写作页面
        ↓
GET current
        ↓
conversation_id 是否为空？
   ├─ 否：恢复会话，直接进入输入页
   └─ 是：展示类型/格式选择
                    ↓
                 POST create
                    ↓
        保存本地 conversation_id
                    ↓
                 POST run
                    ↓
          解析 SSE 事件并展示结果
                    ↓
             用户点击开启新会话
                    ↓
       POST .../{conversation_id}/reset
                    ↓
       清除本地 ID，回到选择界面
```

1. ## 小程序后端改造清单

1. 删除 `/run` 请求中 `inputs.conversation_id`、`inputs.type`、`inputs.format`、`inputs.output_format`；
2. 将本地 `conversation_id` 放到 `/run` 请求体顶层；
3. 将类型/格式选择放到 create 接口；
4. 将 reset 路径改为带 `{conversation_id}`；
5. reset 成功后清除本地 ID，不要接收或生成新的会话 ID；
6. 对 `422`、`404`、`409` 分别处理；
7. SSE 按事件边界解析；
8. 不要把 Dify 原始会话 ID传给用户端；
9. 不要把课程 Excel 或学习路线接口加入本轮实现。
