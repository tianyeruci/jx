# 课程与学习路线合并清洗策略规格计划

## 一、交付目标

本段保留最初的规格阶段边界；规格已经进入实施与验收阶段，以下新增的日期化记录只描述已验证的实现和测试，不把测试数据当作正式目录。

当前实施口径：`COURSE_CATALOG_AUTO_PUBLISH=true` 时走“确定性结构解析 → 模型语义补全 → 价格/契约/隐私/Dify 回读门禁 → 同源原子发布”的自动路径；普通名称冲突、缺少必要来源依据或任一门禁失败都不发布。将该开关设为 `false` 才进入下方的结构审核表和语义审核表人工回退路径。人工路径仍要求管理员确定最终名称，模型不得选择名称。

产出 `docs/课程与学习路线合并清洗策略规格.md`，并同步需求来源追踪和 V2 决策记录。规格包含：

- 老板原始 XLSX 的事实审计与异常清单。
- 原 Word 模板的修订版资料要求。
- “源表字段 → 课程 → 学习路线 → Metadata → 数据库/Redis/Dify”映射。
- `course_route_catalog` 合并清洗策略完整规则。
- 通用大批量 AI 清洗架构、审核机制、失败恢复和验收标准。
- 一组课程、系列、路线的完整输入输出示例。

原模板中“AI生成课程信息必须上传视频”的表述需要修正：视频、字幕或逐字稿不是生成草稿的必要条件，但缺少这些证据时，AI只能生成待审核的低证据强度描述，不能生成具体课节、时间点、效果或承诺。

## 二、数据与接口规格

### 输入和确定性清洗

- 新增策略代码 `course_route_catalog`，第一版只接受 `.xlsx`；原 `course_information`、`learning_route` 保持兼容。
- 工作簿必须有且仅有一个非空工作表，必需列为：
  - `课程名称`
  - `课程链接`
  - `阶段`
  - `学习路线`
- 允许额外列，但只记录审计信息，不自动进入课程正文。
- 当前样本验收基线：
  - 137 条源数据行。
  - 107 个带链接行、105 个唯一链接。
  - 5 个老板提供的路线名称。
  - 2 组重复链接。
  - 父级标题、空白行、“说明”行及“8讲但仅有7条明细”等异常必须生成审计警告。
- 每个规范化唯一链接生成一门课程；同一链接的多行合并。
- 无链接的父级标题只作为 `series_name`；子级标题作为课程名称。重复父子链接时保留子级名称，父级名称作为系列信息或课程重点候选。
- 学习路线名称严格来自源表，不能由 AI 新建；未来上传出现的新路线名称允许进入待审核状态，不硬编码当前5条。
- 源表行顺序只作为审计依据，不能直接视为路线阶段顺序或课程学习顺序。
- 当前阶段值原样受控保留为 `新手必看、入门阶段、高手进阶`，不折叠、不推断先后；未来新值须审核。
- 课程 ID 优先复用数据库中相同规范化链接的既有 ID；否则由程序根据规范化链接生成稳定 ID。
- 路线 ID 优先复用同名路线，否则根据规范化路线名称稳定生成；ID不得由模型生成。

### 课程、路线与审计字段

课程沿用当前 `CourseRecord`，包括：

- `course_id`
- `name`
- `direction`
- `description`
- `official_url`
- `stage`
- `source_platform`
- `series_name`
- `audience`
- `highlights`
- `learning_outcomes`
- `prerequisite_course_ids`
- `enabled`
- `review_status`

路线沿用当前 `RouteRecord`，包括：

- `route_id`
- `name`
- `direction`
- `target`
- `stages[].stage_id`
- `stages[].name`
- `stages[].order`
- `stages[].course_ids`
- `enabled`
- `review_status`

清洗审计信息独立保存，不进入推荐正文：

- 来源工作表及行号。
- 源文件校验值。
- 字段来源：`source`、`deterministic`、`ai`、`human`。
- 模型、Prompt和结构版本。
- AI候选方向、待确认字段和异常警告。
- 幂等键、重试次数和最后错误。
- 不使用缺乏校准依据的“AI置信度数字”替代人工判断。

### AI补全和方向治理

AI只补全语义字段：

- 课程所属方向候选。
- 主要内容或主要解决的问题。
- 适用人群。
- 高层级课程重点。
- 路线适用目标。

AI不得生成：

- 课程链接、课程 ID、路线 ID。
- 老板没有提供的课程或路线。
- 路线阶段顺序、课程学习顺序。
- 前置课程关系。
- 具体课节、视频时间点。
- 收益、效果、结果保证或营销承诺。

方向采用动态受控字典：

- 老板资料明确给出方向时，以原文作为候选。
- 缺失时由 AI 提议，不采用旧模板示例作为默认权威值。
- 管理员将候选映射到已有方向，或明确批准为新方向。
- 同义词映射到同一规范名称。
- 未完成方向审核的课程和路线不能发布。
- 现有课程和路线仍保存规范化方向字符串，避免破坏当前推荐接口；方向字典负责治理规范值和别名。

人工回退路径中，所有含 AI 字段的课程均进入 `pending_review`；路线除了语义字段审核，还必须由人工补齐阶段顺序和阶段内课程顺序，才能批准。自动路径不把模型输出当结构事实：名称、链接、稳定 ID、路线归属和顺序只来自解析结果，只有价格、模型契约、隐私和 Dify 回读全部通过才会写入已批准的课程/路线记录。

### 知识库、数据库和 Redis

- PostgreSQL继续作为课程、路线、审核状态、阶段关系和正式链接的唯一权威源。
- Redis `ai:course:snapshot`只保存已启用、已批准的有效推荐快照，可由数据库重建。
- Dify只保存课程和路线的检索副本。
- 课程链接不得进入：
  - Dify正文。
  - Dify Metadata。
  - 模型输入。
  - 问答上下文。
- 推荐卡片继续通过服务端签名跳转，不向模型或前端暴露原始链接字段。
- 课程 Metadata：
  - `document_type=course`
  - `course_id`
  - `direction`
  - `stage`
  - `source_platform`
  - 可选 `series_name`
  - `status`
- 路线 Metadata：
  - `document_type=learning_route`
  - `route_id`
  - `direction`
  - `status`
- 不恢复旧计划中的 `learning_path` 等过时字段名。

## 三、批量处理与可靠性架构

- 程序负责解析、拆分、队列、并发、限流、幂等、审核、发布事务和补偿。
- 模型通过可插拔 `SemanticEnricher` 接口调用；首个实现直接调用兼容模型接口，同时保留 Dify Workflow 适配器扩展点。
- Dify Workflow不承担海量清洗总编排；Dify继续用于知识库与在线商业顾问问答。Dify自身存在活跃请求、执行时间及Worker配置边界，不应作为批量可靠性的唯一控制层。[Dify官方部署配置](https://github.com/langgenius/dify/blob/main/docker/.env.example)
- 处理阶段拆分为：
  1. 文件签名与格式验证。
  2. 确定性解析、去重和稳定 ID。
  3. 按路线/系列和 token 预算拆分语义任务。
  4. 后台 Worker 调用模型并校验结构化输出。
  5. 自动路径执行价格、模型契约、隐私和 Dify 回读门禁；人工回退路径执行结构审核、方向映射、语义审核和路线排序。
  6. Dify候选文档发布与索引/Metadata复核。
  7. 数据库原子提交。
  8. Redis临时快照构建并原子替换。
- 不按“文件数”或固定记录数设置模型批次；按上下文 token、输出预算和语义边界拆分。
- 并发由模型 RPM、TPM、Worker资源和实时429响应共同限制，支持退避和背压。
- 幂等键由源校验值、记录稳定 ID、Prompt版本、模型版本和结构版本组成；重复上传不得产生重复课程或重复模型任务。
- 模型超时、限流、非法 JSON 或部分缺项只能重试对应语义任务；不得重新执行已完成记录。
- 模型不可用时保留确定性解析结果和断点，状态停留在待补全，禁止发布半成品。
- 课程与路线可并发清洗，但发布时必须先校验课程，再校验引用这些课程的路线。
- 同一源文件继续保持全有或全无发布；任何待审核或失败条目都会阻止该文件其余条目发布。
- Dify索引、父子块或 Metadata 复核失败时删除或禁用本次候选文档；数据库提交失败时旧权威记录不受影响。
- Redis重建失败不回滚已提交数据库，记录修复任务并由数据库重新构建。

性能采用压测定基线：

- 正确性硬门槛为无丢失、无重复、可断点恢复、可审计和可补偿。
- 使用模拟模型验证十万级任务调度和500万–1000万字分片。
- 使用真实模型的小规模阶梯压测确定单批 token、Worker并发、RPM/TPM和成本。
- 未取得模型供应商配额和真实压测结果前，不承诺“6小时”或“24小时”等虚假固定时长。

## 四、验收测试

- 当前 XLSX 必须稳定产出105个课程候选和5个路线草稿，不因重复链接生成重复课程；自动路径还必须验证同源 110 个候选全部通过或整体阻断，不允许部分发布。
- 父级标题、重复父子链接、空行、说明行、缺失链接、未知域名和讲数不一致分别有明确结果或警告。
- 新路线名称可以进入待审核，不受当前5条样本限制。
- 当前三个阶段值保持不变且没有隐含顺序。
- AI不得修改名称、链接、源阶段、路线名称或稳定 ID。
- AI输出缺字段、增加不存在课程、产生营销承诺或不符合结构时必须拦截。
- 新方向须经过映射或批准；同义方向不得形成多个正式值。
- 未确认路线顺序时，课程可以形成审核草稿，但路线不能进入有效推荐快照。
- 重复上传、同名/同内容保护、精确源删除后的去重释放、任务超时、Worker重启、429、模型异常、Dify索引失败、数据库提交失败和Redis重建失败均有故障注入或定向回归测试。
- 验证链接只存在于数据库和Redis快照，不出现在Dify正文、Metadata、模型请求、日志和公开问答。
- 验证同源文件发布的原子性、旧文档保留和失败补偿。
- 验证商业顾问仅推荐已批准课程和路线，直接课程查询、路线推荐、阶段确认及签名跳转行为保持兼容。

## 五、已锁定假设

- 当前样本只以老板提供的表格为事实来源，不使用无法认证访问的课程页面。
- 老板提供的5个名称是路线样本，不是完整路线字典，也不是方向字典。
- AI生成内容只是待审核候选，不因语言流畅而视为事实。
- 路线及课程学习顺序由业务方确认，AI和源表行序都不能替代。
- 方向采用动态受控字典；旧模板中的方向只保留为历史示例。
- 原规格阶段只输出规格和文档映射，不修改程序、数据库、Dify、Redis或正式数据；后续实施与验收必须遵循本规格并使用独立测试数据，正式目录仍需单独审批。

## 六、2026-08-01 实施核验补充

- `course_route_catalog` 已按本规格接入管理页和后台 Worker：解析、稳定去重、模型语义候选、审核表导入、课程/路线权威记录、Dify 发布和 Redis 快照均走同一条可追踪链路；正式目录不因本轮测试改写。
- 用户指定的 `课程信息与学习路线.xlsx` 的 XML 实际包含完整五列（含可选的 `课程序号`）和 138 行；问题是工作簿 `<dimension ref="A1">` 元数据过期，`openpyxl` 默认只读取到 A1。解析器现在先 `reset_dimensions()` 再流式读取，并以本地与服务器同 SHA-256 的原样本核对，得到 137 条有效源行、105 个课程实体、5 条路线和 2 组同链接冲突。冲突必须先结构审核，不得由模型选择名称。
- 课程目录结构审核使用独立工作簿：管理员确认最终课程名称、合集和顺序后，才进入模型补全；模型只补方向、描述、适用人群、亮点、目标和路线目标，不能修改名称、链接、课程 ID、路线归属或顺序。
- 使用符合四列契约的脱敏合成工作簿复测：3 条课程记录、2 条路线记录经模型候选和人工审核表导入后，5 份 Dify 文档均完成索引和父子块回读；课程/路线 Metadata 满足白名单，正文和 Metadata 均不含 URL 或邮箱。
- qwen-plus 在一次候选生成中将应为文本的字段返回为列表；实现已在结构化契约层把允许的文本列表规范化为带分隔符的文本，同时仍拒绝 URL/链接和不符合字段形状的对象，并有模型契约回归测试。不能把模型输出原样写入正式目录。
- 人工回退路径的课程/路线 AI 字段仍必须经过人工审核；默认自动路径只允许来源事实和结构化契约支持的语义字段进入发布门禁，不能用合成验收替代生产数据复核。合成验收完成不等于 137 行正式目录已经导入。

### 2026-08-02 实施补充

- 默认 `COURSE_CATALOG_AUTO_PUBLISH=true` 时，管理页只需选择策略并上传 XLSX；不展示费用确认或结构审核表操作。解析先固定源名称、稳定 ID、正式链接、路线归属和顺序，模型只补方向、描述、适用人群、亮点、学习目标和路线目标。
- 自动模型任务只在价格版本、生效/失效日期和正价格均有效且预估费用上限不超过 `COURSE_CATALOG_AUTO_APPROVE_COST_MAX`（默认 1.0）时入队；价格、模型契约、隐私或 Dify 结构回读任一失败，整源文件统一 `CATALOG_AUTO_PUBLISH_BLOCKED`，不发布部分记录。自动关闭后继续使用原人工审核回退路径。
- 测试环境可通过 `BAILIAN_BATCH_ENABLED=false` 将新模型任务切换到实时 Worker；已有任务保持创建时模式。Batch 与实时调用分别保存价格版本、日期和单价快照，实时模式不套用 Batch 折扣；课程自动门禁始终按实际模式校验价格和费用上限。
- 路线模型请求除路线名称/目标外，补充解析得到的阶段及课程名称作为来源上下文；描述为空时只可由输入来源字段组成事实摘要，方向或路线目标仅在源字段已有值时允许来源兜底，源与模型均无依据仍阻断，不能用路线名称、阶段顺序或默认文本猜测。
- 空链接课程名称行定义课程合集边界；有链接行中同时出现 `【分类】N讲（时长）` 与具体标题时，自动保留具体标题并记录脱敏告警，不把有链接标题误当合集。两个普通名称仍阻断并要求人工确认。一个课程重复出现在多条路线时只保留一个 `course_id`，各路线分别引用该 ID。
